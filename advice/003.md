# 2. P0-1：Region B 的 pruning 判据仍然错了

这是目前最重要的问题。

你们现在已经正确写出了三区域：

[
\begin{aligned}
A:&\quad c_1\le h<c_{\rm dir},\
B:&\quad c_{\rm dir}\le h<c_1+c_2,\
C:&\quad h\ge c_1+c_2.
\end{aligned}
]

而 `advice/002.md` 中理论本身也是正确的：

# [ Q_{\rm prog}-Q_{\rm dir}

\begin{cases}
\text{N/A}, & A,\
E[Y], & B,\
E[\min(Y,b)], & C.
\end{cases}
]

但是代码没有按这个 piecewise law 做 pruning。

当前 `phase_support_budget()` 中，第二层 refinement 的 conditional future risk `E_R` **只有 Region C 才计算**：

```python
if ref is not None and region == "C":
    ...
    E_R += ...
```

然后不管 B/C，都生成：

```python
D = R1 - E_R
Y = D - d2
g0 = E[min(Y, BH)]
```

最终 pruning 条件仍统一为：

```python
prune_probe_ok = (g0 >= 0.0) and dir_feas
```

### 为什么 Region B 错

在 Region B：

[
c_{\rm dir}\le h<c_1+c_2,
]

第二包不能发，所以

# [ Q_{\rm prog}^{B}

c_1+E[R(X_1)].
]

Direct 是：

# [ Q_{\rm dir}

c_{\rm dir}+E[R(X_2)].
]

因此：

[
\begin{aligned}
Q_{\rm prog}^{B}-Q_{\rm dir}
&=
c_1-c_{\rm dir}
+
E[R(X_1)]-E[R(X_2)]
\
&=
-d_2+E[D]
\
&=
\boxed{E[Y]}.
\end{aligned}
]

所以 Region B 应当判断的是：

[
\boxed{
g_B=E[Y]\ge0.
}
]

而不是：

[
E[\min(Y,b)]\ge0.
]

更严重的是，当前 Region B 中代码根本没有计算 counterfactual (E[R(X_2)|X_1])，于是代码里的 `Y` 实际变成了：

[
Y_{\rm code}=R(X_1)-d_2,
]

并不是 theorem 里的：

[
Y=
R(X_1)-E[R(X_2)|X_1]-d_2.
]

所以 Region B 的 `g0` 在数学定义上已经不是同一个量。

# 4. 正确的修法很简单

我不建议再增加复杂 planner。

直接把 phase gap 定义成 piecewise 即可：

# [ G_i(s,h)

\begin{cases}
-\infty, &
c_1\le h<c_{\rm dir},
\[1mm]
E[Y],&
c_{\rm dir}\le h<c_1+c_2,
\[1mm]
E[\min(Y,b_i)],&
h\ge c_1+c_2.
\end{cases}
]

其中 (-\infty) 的含义不是 cost，而是：

> direct 不可行，因此不存在“direct dominates probe”。

安全剪枝就是：

[
\boxed{
\text{prune probe}
\iff
c_{\rm dir}\le h
\land
G_i(s,h)\ge0.
}
]

代码层最保险甚至可以直接写：

```python
if region == "A":
    prune_probe = False

elif region == "B":
    gap = Q_prog - Q_dir
    prune_probe = gap >= -tol

elif region == "C":
    gap = g_phase
    prune_probe = gap >= -tol
```

然后理论验证再单独确认：

[
\boxed{
Q_{\rm prog}-Q_{\rm dir}=E[Y]
}
]

在 B 成立，以及：

[
\boxed{
Q_{\rm prog}-Q_{\rm dir}=E[\min(Y,b)]
}
]

在 C 成立。

这比把 `g0` 强行做成所有 region 的统一变量更干净。

[
U_{FA}\le0.05

[
(\rho,\eta)=(8192,1.6),

[
U_{FA}=0.0422,

[
U_{MD}=0.2446.

因此 calibration 上真正的差距应该是约：

# [ 0.2446-0.1591

# 10. P1：MITM reference 还有一个 NP 语义问题，最好现在一次封死

当前 `pd_max_at_alpha()` 用的是 deterministic：

[
\Omega>\eta.
]

对于离散 quantized LLR distribution，严格的 Neyman–Pearson optimum 在 threshold atom 上可以允许随机化：

[
\delta=
\begin{cases}
1,&\Omega>\eta,\
\gamma,&\Omega=\eta,\
0,&\Omega<\eta.
\end{cases}
]

从而恰好满足：

[
P_{FA}=\alpha.
]

当前 deterministic threshold 得到的实际上更准确叫：

[
P_{D,\max}^{\rm det-thr}(\alpha).
]

这对 8-bit support 很密集，数值影响可能极小，但对 4-bit 未必严格为零。

所以建议二选一：

1. 明确论文定义：“所有检测器均使用 deterministic LLR threshold”，那么现在算法完全合理；
2. 或者 MITM 增加 threshold-atom randomization，得到严格 NP (P_{D,\max})。

不要留一个 reviewer 可以追问的定义缝隙。

同时报告中的：

> (P_{FA}=\alpha=0.05)

建议暂时改成：

[
P_{FA}\le\alpha
]

除非你实际计算并打印了 randomized boundary。
