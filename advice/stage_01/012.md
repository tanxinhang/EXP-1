## 1. 最重要的问题：当前“11 次 certified override”其实不是 formal certificate

正式报告里的 11 次 override：

> `betting-mode CPI`，safe=11，violations=0。

cpi = CPI(..., cs_mode="betting")

且 6000 worlds 下 override rate=0。

- `eb` = theorem-backed formal path；
- `betting` = finite-grid experimental ablation，**没有严格 continuum guarantee**。

因此目前只能写：

[
\boxed{\text{11 empirically safe operational overrides}}
]

不能写：

[
\boxed{\text{11 formally certified overrides}}

更不能对 betting path 声称：

[
P(\text{violation})\le\sum_t\delta_t.

### 正确分层

建议以后固定两个名字：

- **Formal-CPI**：`cs_mode="eb"`，承担 theorem / safety claim；
- **Operational-CPI**：`cs_mode="betting"`，承担性能探索，不能承担严格置信保证。

这点非常重要，否则 B0.4r 自己建立的“formal vs experimental”边界在 B0.4a 又被打破了。

# 3. formal-EB override=0 的实验现在有一个真实 evaluation bug

这一点比较隐蔽。

前面的 100-state betting CPI 循环里：

```python
delta_t = 6 * delta_episode / (pi**2 * (s+1)**2)
```

循环结束后，`delta_t` 保留的是最后一个状态、也就是近似：

[
t=100
]

时的值。

但后面的 formal-EB subset：

```python
for s in range(n_eb):
    ...
    cpi.decide(..., delta_t=delta_t, ...)
```

**没有重新计算 `delta_t`。**

也就是说 15 个 formal-EB test states 全部使用了大约：

# [ \delta_{100}

\frac{6(0.05)}{\pi^2 100^2}
\approx3.0\times10^{-6}.
]

decision 内又除以 pair 数 (P)，置信预算会更小。

所以：

> “formal EB 6000 worlds override≈0，因为 formal EB 太保守”

目前这个结论**不能成立**。

至少有相当部分是因为实验错误地用了 (t=100) 的极小 (\delta_t)。

### 修复

静态 state Gate 如果每个 state 是独立 episode 的第一决策，应使用：

[
\delta_1=
\frac{6\delta_{\rm episode}}{\pi^2}.
]

或者专门扫：

[
t\in{1,2,4,8}
]

报告：

[
P_{\rm override}(t).
]

真正的 episode-level (\delta_t) 必须在后面的**实际 receding episode trajectory** 中测试，而不是拿 100 个独立 random states 当 (t=1,\ldots,100)。

# 4. 当前 (O(|A|)) confidence-budget claim 与实现不一致

报告写：

> base-anchored，(O(|A|)) 而非 (O(|A|^2)) confidence budget。

但 CPI 实际代码仍然：

# [ P

\frac{(|A|+1)|A|}{2},
]

然后：

# [ \alpha_{\rm pair}

\frac{\delta_t}{P}.
]

也就是说置信分配仍是：

[
\boxed{O(|A|^2)}
]

all-pairs union allocation。

这也是 formal EB 很难 override 的原因之一。

### 两种真正实现 (O(|A|)) 的方式

我更推荐第一种。

**方案 A：固定 base-anchor**

始终比较：

[
\Delta_{c,a_b}.
]

只允许：

[
U_{c,a_b}<0
]

的 candidate 成为 override。

则最多只有：

[
|A|-1
]

个 pair：

[
\boxed{\alpha_c=\delta_t/(|A|-1)}.
]

其实完全不需要 candidate-vs-new-incumbent 的 all-pairs chain。

只要最终：

[
Q_c^{\pi_b}<Q_{a_b}^{\pi_b},
]

policy-improvement condition 就已经满足。

**方案 B：adaptive query spending**

第 (q) 个新 pair 分：

# [ \delta_{t,q}

\frac{6\delta_t}{\pi^2q^2}.
]

这样无需事先按 (\binom{|A|}{2}) 分配。

这对大 UAV 数更自然。

# 5. 更深的一处理论语义问题：当前 CPI anchor 和 rollout base 不完全是同一个 (\pi_b(x,h))

这是我认为 B0.4a-r 必须解决的另一项 P0。

CPI 初始化 base action 时：

```python
a_b = self.base.act(cr.pl, x_int, om, h=h)
```

所以 VoIBase 会在**当前预算 h 内重新找最优可行动作**。

但是 rollout 中：

```python
a = self.base.act(self.pl, x2, om2)
```

**没有传 `h_rem`**。

如果 base 选中的动作超过剩余预算：

```python
if c > h_rem:
    break
```

直接 STOP。

exact oracle `base_policy_value()` 也是：

```python
a = crr.base.act(crr.pl, x_int, om)
```

不传 h；若动作太贵，则直接终止。

因此存在：

[
\pi_b^{\rm CPI-anchor}(x,h)
\neq
\pi_b^{\rm rollout}(x,h).
]

例如 unconstrained VoI 最优 action 超预算，但第二优 action 可行：

- CPI anchor 会选第二优可行动作；
- rollout/exact base 会选第一优，然后发现付不起，直接 STOP。

这时：

# [ Q^{\pi_b}(x,a_b)

V^{\pi_b}(x)
]

这个 policy-improvement 起点不一定成立。

### 推荐修法

把 base policy 正式定义在**增广状态**

[
s=(x,h)
]

上。

所有路径统一调用：

```python
base.act(pl, x, omega, h=h_rem)
```

包括：

- CPI initial anchor；
- `_rollout()`；
- `base_policy_value()`；
- exact Q oracle。

这样才真正有：

[
\boxed{
a_b=\pi_b(x,h)
}
]

以及：

# [ \boxed{ Q^{\pi_b}(x,h,a_b)

V^{\pi_b}(x,h).
}
]

然后 policy-improvement theorem 才完全干净：

[
Q^{\pi_b}(s,\pi_{\rm CPI}(s))
\le
V^{\pi_b}(s)
\quad\forall s
]

推出：

[
\boxed{
V^{\pi_{\rm CPI}}(s)
\le
V^{\pi_b}(s).
}
]

# 6. VoIBase 的实验结果也告诉了我们一件重要事情：它现在不是“更强 fallback”

G0：

| fallback  | E[gap] | P(gap>2) |
| --------- | ------ | -------- |
| empirical | 1.51   | 0.30     |
| SNR       | 3.16   | **0.17** |
| VoI       | 3.57   | 0.29     |

所以不能说：

> VoI-base 比 SNR-base 更强。

它的优势目前只是：

> **objective-consistent / interpretable / header-aware**

而不是 action-quality 已经更优。

这其实是一个很有价值的结果。

说明 one-step VoI 是：

[
\text{better theoretical anchor}
]

但还不是：

[
\text{better performance anchor}.
]

因此 B0.4a-r 应至少加入：

[
\boxed{
\text{CPI@SNR-base}
\quad\text{vs}\quad
\text{CPI@VoI-base}
}
]

同 states、同 rollouts、同 (\delta)。

这会决定最终论文算法到底应该：

- 用 VoIBase；
- 用 SNRBase；
- 还是用 VoI 作为 candidate ranking，而 SNR 作为 safe anchor。

第三种其实很有可能最好。
