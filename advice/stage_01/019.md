# 2. 还剩一个理论表述问题：(\rho) 的解释要再改一句

当前 runner 写的是：

> 当前 (\pi_0=\pi_1=0.5)，所以 (R_{\rm exact}=2R_{\rm code})，仅统一缩放 2 倍，不改变 (\hat\theta) 选择次序/可行性。

这里后半句还是不严格。

因为如果真的把 terminal risk 从

[
R
]

变成

[
2R,
]

而通信成本

[
c_a
]

不变，那么

[
R
\mathop{\lessgtr}
c_a+E[R']
]

的 stopping condition **可能改变**。

换言之：

[
R\rightarrow 2R
]

不是 harmless scaling，因为通信 bit cost 没同时乘 2。

### 正确解释非常简单

不要说：

> exact risk 是 code risk 的两倍，但两倍不影响策略。

而直接定义：

[
\bar\lambda_M
\triangleq
\lambda_M/\pi_1,
\qquad
\bar\lambda_F
\triangleq
\lambda_F/\pi_0,
]

然后参数化

[
\boxed{
\rho=\bar\lambda_M,\qquad
\rho e^\eta=\bar\lambda_F.
}
]

于是 conditional-error Lagrangian 的 terminal Bayes risk 本来就是

# [ R_{\rho,\eta}(p)

\min{
\rho p,\rho e^\eta(1-p)
}.
]

也就是说：

[
\boxed{\text{代码本身就是 exact effective-multiplier parameterization}}
]

根本不需要出现“再乘 2”这一步。

这样理论最干净，而且**完全不改数值**。

这个属于 P1-theory，不是代码错误。

# 7. 那原来的 2 bit 怎么办？

可以保留，但把它从**唯一 ADOPT criterion**降成 minimum effect size：

[
\delta_B=2\text{ bits/episode}.
]

[
U_{95}(E[D_B])<-\delta_B.

但应该明确：

> (\delta_B) 是 **minimum practically relevant communication saving**，不是算法复杂度本身的代理。

[
\delta_B\approx5%\times E[B^{base}]

甚至可以预注册成：

# [ \boxed{ \delta_B

0.05,E_{\rm cal}[B^{base}]
}

而不是绝对 2。

不过如果 README 中 2 bits 已经正式 preregistered，我不建议为了追求漂亮现在不断改阈值。**保留 2 bits 也可以，但必须把它解释为 effect-size threshold，而不是 complexity penalty。**
