# 二、P0-1：当前“matched 机制层不可达”的定性仍然过强

这是我认为 C2.1 必须首先修的地方。

当前 4-bit 系统：

[
N=4,\qquad b_0=16,\qquad r_{\max}=4.
]

4 架 UAV 全部 Direct4 的路径成本只有

[
4(16+4)=80<96.
]

而 C2 自己已经精确得到：

[
P_{D,\max}^{4b}(0.05)=0.8482,
]

matched 要求只有

[
P_D\ge0.8382.
]

因此，在 (H=96) 下，**“强制四架全部发送 4-bit”就是一个显式的可行构造**。它最终产生的就是定义 (P_{D,\max}^{4b}) 所使用的 full-message statistic。

所以数学上已经有：

[
\boxed{\exists\pi:;
C_\pi\le96,;
P_{FA}\le0.05,;
P_D\ge0.8382.}
]

这意味着：

[
\boxed{\text{N=4,H=96 matched problem 本身并非 mechanism-infeasible。}}
]

现在得到 INFEASIBLE，是因为代码只扫了

[
\rho\in{128,256,512,1024}
]

和一个有限 (\eta) 网格，并且 controller 自己仍然在做通信成本与 terminal risk 的 scalarized tradeoff。当前报告也显示所有 matched calibration 最终都撞到 (\rho=1024) 边界，这本身就是一个典型的 **dual search domain saturation** 信号。

### 应当怎么修

不要直接把 (\rho_{\max}) 从 1024 改成 8192 然后再跑一次，这太经验化。

应做 **dual homotopy / feasibility closure**：

[
\rho=128,256,512,1024,2048,4096,\ldots
]

直到发生下面二者之一：

[
\text{matched FEASIBLE}
]

或者证明：

[
\pi_{\rho}\rightarrow \pi_{\rm full}
]

之后仍然无法满足目标。

甚至可以直接对两个 error multiplier 做约束驱动更新：

# [ \lambda_M^{k+1}

\left[
\lambda_M^k+
\tau_k(P_M-\beta)
\right]_+,
]

# [ \lambda_F^{k+1}

\left[
\lambda_F^k+
\tau_k(P_{FA}-\alpha)
\right]_+.
]

这样“dual 参数”真正是为了满足 QoS，而不是人为扫一个有限矩形。

### 文档建议

把：

> matched mechanism-level INFEASIBLE

改成：

> **matched QoS is not attained by the registered finite dual grid/controller family; this does not imply primal infeasibility.**

这个措辞会严谨很多。

# 三、P0-2：Gate D 当前仍然不是一个正确的“solver-quality certificate”

这其实比上一轮发现的“拿 (V_{\rm lag}) 当通信成本”还更微妙。

现在你们把 Gate D 改成了：

## [ \frac{ E[B]_{\rm Phase}

E[B]*{\rm CMDP^\star}
}{
E[B]*{\rm CMDP^\star}
}.
]

然后 H=96 出现：

- (-13.52%)
- (-4.74%)
- (-7.89%)
- (-8.25%)

并解释为 Phase-FG 用更大的 terminal risk 换更少 bits。

这个解释本身没错。

**错的是：既然 terminal risk 不一样，那么这个 (E[B]) gap 就不能拿来认证 solver quality。**

因为 exact `SparsePlanner` 实际解决的是：

# [ V^\star_\theta(s,h)

\min
\left{
R_\theta(s),
\min_{a:c_a\le h}
[
c_a+
E V^\star_\theta(S',h-c_a)
]
\right}.
]

代码确实如此：STOP value 是 Bayes/dual terminal risk，而 continuation value 是 communication cost 加后续 value。

因此 fixed-(\theta) oracle 真正最优的是：

# [ \boxed{ J_\theta(\pi)

E_\pi[C]
+
E_\pi[R_\theta(S_\tau)]
}
]

而不是单独的 (E[C])。

### 正确的 Gate D 应拆成两个 Gate

**D1 — fixed-dual solver-quality**

# [ \boxed{ \Delta_J

\frac{
J_\theta(\pi_{\rm Phase})-V_\theta^\star
}{
V_\theta^\star
}
\ge0
}
]

要求比如：

[
\Delta_J\le10%.
]

这里才是真正的 approximation-quality certificate。

**D2 — primal communication efficiency**

只有双方都满足同样的：

[
P_{FA}\le\alpha,\qquad
P_D\ge P_{D,\max}-\epsilon_D
]

后，才比较：

## [ E[C_{\rm Phase}]

E[C_{\rm oracle}].
]

换句话说：

> 上一版“Phase E[B] vs (V_{\rm lag})”确实错；
>
> 但现在“Phase E[B] vs oracle E[B]”作为 solver-quality 仍然不对。
>
> **正确做法是 Phase (J_{\rm lag}) vs exact (V_{\rm lag})**。

当前 Gate D 用“signed E[B] gap 的最大值”判断 PASS，有一个逻辑漏洞：即使某些点是 (-50%)，只要最大的正值仍小于 10%，照样 PASS；这并不构成任何近最优保证。

所以 **C2 当前的 Gate D PASS 建议暂时降级为 `PROVISIONAL PASS`**。

# 四、P0-3：hard budget 下的 phase pruning 目前存在真实的可行动作误删 bug

这是代码层我认为最值得修的一处。

当前 `phase_decision()` 逻辑大致是：

```python
if g0 >= 0:
    # prune probe
    if direct fits:
        keep direct
else:
    keep feasible probe/direct
```

也就是说：

[
g_{s,i}(b_i)\ge0
\Rightarrow
\text{删除 probe}.
]

这个结论在**无 budget boundary**时成立，因为 theorem 比较的是：

[
Q^{prog}_i
\quad\text{vs}\quad
Q^{dir}_i.
]

但是如果当前剩余资源为 (h)，出现：

[
c_{\rm probe}\le h<c_{\rm dir},
]

那么 direct 已经根本不可行。

此时即便

[
Q^{prog}\ge Q^{dir},
]

也不能用一个**不可行的 direct action**去支配并删除一个**可行的 probe action**。

举个当前 8-bit fresh UAV 的直接例子：

[
c_{\rm probe}=16+1=17,
]

[
c_{\rm dir}=16+8=24.
]

如果：

[
h=20,
]

则：

- probe 可行；
- direct 不可行。

但当前若 (g_0\ge0)，代码会把 probe 删掉，从而可能错误 STOP。

所以安全剪枝真正需要的是：

[
\boxed{
g_{s,i}(b_i)\ge0
;\land;
c_{\rm dir}\le h
\Rightarrow
\text{probe can be pruned}.
}
]

而不是单独：

[
g\ge0.
]

这不是性能调参，而是 **constrained dominance 的基本数学条件**。

# 五、这里反而可以导出一个比现有 phase theorem 更好的新理论

这次 bug 可以直接升级成论文贡献。

令：

[
c_1=b+d_1
]

为 probe cost，

[
c_2=b+d_2
]

为第二次 refinement transaction，

而 direct jump：

[
c_d=b+d_1+d_2.
]

定义：

# [ D(X_1)

## R(X_1)

E[R(X_2)|X_1],
]

[
Y=D-d_2.
]

现有 theorem 在资源充足时给出：

# [ Q_{\rm prog}-Q_{\rm dir}

E[\min(Y,b)].
]

但注意：

# [ c_1+c_2

c_d+b.
]

progressive 因为发生了两次 transaction，所以需要额外付一次 setup。

把剩余 frame resource (h) 加进去，可以得到一个非常漂亮的 **resource-window-aware phase law**：

# [ \boxed{ Q_{\rm prog}(h)-Q_{\rm dir}(h)

\begin{cases}
\text{N/A: direct infeasible},&
c_1\le h<c_d,
\[1mm]
E[Y],&
c_d\le h<c_1+c_2,
\[1mm]
E[\min(Y,b)],&
h\ge c_1+c_2.
\end{cases}
}
]

第一段最重要：

[
c_1\le h<c_d
]

时，**probe 是唯一可行结构动作，绝对不能被 phase pruning 删掉**。

第二段：

[
c_d\le h<c_1+c_2
]

时，direct 可行，但 progressive 的“第二包”不可行，因此：

# [ Q_{\rm prog}

c_1+E[R(X_1)]
]

而不再是当前代码使用的 conditional refinement expression。

第三段才恢复原 theorem：

[
E[\min(Y,b)].
]

这比现在单纯的：

> Feedback-Granularity-Aware Adaptive Evidence Acquisition

还更有理论辨识度。我建议提升成：

[
\boxed{
\textbf{Resource-Window-Aware Feedback Granularity Control}
}
]

或者：

[
\boxed{
\textbf{Frame-Feasible Adaptive Evidence Packetization}
}
]

这是真正由通信物理约束导出的 phase transition，不是人为加一个 heuristic。

# 七、P1：8-bit full-fusion reference 其实不需要退回 continuous raw reference

当前 C2 写的是：

> 256⁴ 太大，因此 8-bit exact convolution 不可行，改用 continuous full-fusion (P_{D,\rm raw})。

这里“不能直接建立 (256^4) dictionary”没错。

但“因此 N=4 的 exact 8-bit full-fusion ROC 不可算”并不成立。

可以用 **meet-in-the-middle**。

把四个 UAV 分成：

[
A=(1,2),\qquad B=(3,4).
]

每一侧只需要：

[
256^2=65536
]

个 pair sums。

对每个 hypothesis (h) 建：

[
(s_A,w_A^{(h)}),\qquad
(s_B,w_B^{(h)}).
]

将 B 的 (s_B) 排序，建立 suffix probability：

# [ W_B^{(h)}(x)

\Pr_h(s_B>x).
]

那么任意 threshold (\eta)：

# [ \boxed{ P_h(\Omega>\eta)

\sum_A
w_A^{(h)}
W_B^{(h)}(\eta-s_A).
}
]

复杂度约为：

[
O(256^2\log256^2),
]

内存也是：

[
O(256^2),
]

而不是：

[
O(256^4).
]

所以：

> **8-bit dynamic CMDP 仍然不可行；**
>
> **但 8-bit full-report ROC reference 完全可以精确算。**

这是两个完全不同的问题。

而 `SystemModel.md` 本身已经明确要求严格区分：

[
P_{D,\rm raw}
]

和：

[
P_{D,\max}
]

即 continuous upper bound 与 maximum-message achievable reference。

因此建议在 C2.1 中把：

[
BETA8=1-P_{D,\rm raw}+\epsilon_D
]

彻底替换成真正的：

# [ \boxed{ BETA8

1-P_{D,\max}^{8b}+\epsilon_D.
}
]

这样 paper semantics 就完全闭合了。

# 十、我建议新增一个“Matched-QoS 可达性 Gate”，这会显著提高理论层次

现在最大的教训就是：

> controller 没达到 QoS
> (\neq)
> QoS 在这个通信预算下不可达到。

这可以用信息论做一个真正的 feasibility certificate。

令完整 adaptive transcript 为：

# [ \mathcal T

(A_1,M_1,\ldots,A_\tau,M_\tau).
]

根据 KL chain rule：

# [ D(P_1^{\mathcal T}\Vert P_0^{\mathcal T})

E_1
\left[
\sum_t
D(
P_1(M_t|S_t,A_t)
\Vert
P_0(M_t|S_t,A_t)
)
\right].
]

而最终 decision 是 transcript 的函数，所以数据处理不等式给出：

[
D(P_1^{\mathcal T}\Vert P_0^{\mathcal T})
\ge
d(P_D\Vert P_{FA}),
]

其中 (d(\cdot\Vert\cdot)) 是 Bernoulli KL。

如果目标是：

[
P_D\ge1-\beta,\qquad P_{FA}\le\alpha,
]

则必要的信息量约束为：

[
\boxed{
D(P_1^{\mathcal T}\Vert P_0^{\mathcal T})
\ge
d(1-\beta\Vert\alpha).
}
]

再定义每单位通信资源最多能买到的信息：

# [ \kappa_{\max}

\sup_{s,a}
\frac{
D(P_1(M|s,a)\Vert P_0(M|s,a))
}{
c(s,a)
}.
]

pathwise：

[
C(\omega)\le H
]

立即给出：

[
D(P_1^\mathcal T\Vert P_0^\mathcal T)
\le
\kappa_{\max}H.
]

从而得到必要条件：

[
\boxed{
H
\ge
\frac{
d(1-\beta\Vert\alpha)
}{
\kappa_{\max}
}.
}
]

这个 bound 可能不紧，但非常有价值，因为它能把三种情况分开：

| 结果                   | 结论                        |
| ---------------------- | --------------------------- |
| 信息上界 < required KL | **PROVABLY INFEASIBLE**     |
| 某实际策略通过 QoS     | **CONSTRUCTIVELY FEASIBLE** |
| 两者之间               | **UNRESOLVED**              |

这样以后就不会再出现“网格失败 → 机制不可达”这种定性风险。

而且这正好把：

[
\text{sensing information}
]

和：

[
\text{communication resource}
]

真正通过一个数学量联系起来。

这会比再做一个 CPI / RL 模块更有论文价值。

# 十三、从文献角度看，现在的创新定位应该继续收窄，而不是继续扩展模块

这一点当前方向是对的。

反馈、quantization、ordered transmission 和 fading 本身已经被 FE-SRTS 系统性联合考虑，因此这些不能再单独作为 novelty。([IISc ECE](https://ece.iisc.ac.in/~nextgenwrl/papers/Sayantan_2024_TCOM.pdf?utm_source=chatgpt.com))

在线 sensor selection + optimal stopping + usage cost 也已经有比较成熟的 Bayesian DP 理论。([Experts@Minnesota](https://experts.umn.edu/en/publications/sequential-hypothesis-test-with-online-usage-constrained-sensor-s-2/?utm_source=chatgpt.com)) Successive-refinement hypothesis testing 更是已有经典信息论基础。([IBM Research](https://research.ibm.com/publications/hypothesis-testing-under-successive-refinement-communication-constraints?utm_source=chatgpt.com))

另一方面，2026 年的 multi-UAV/cooperative ISAC 工作仍主要围绕 association、trajectory、bandwidth、beamforming、power 等物理资源优化；协同感知带来的 signaling/resource burden 仍然是明确问题。([arXiv](https://arxiv.org/abs/2603.11502?utm_source=chatgpt.com))

所以你现在真正有辨识度的，不应该是：

> UAV selection + quantization + feedback
