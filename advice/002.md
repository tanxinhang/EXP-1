# 二、现在最大的新增发现：5.9855 bits 还不能叫“Exact constrained optimum”

当前 G3/G4 表里：

[
DP:\quad
P_D=0.8458,\quad P_{FA}=0.05,\quad E[B]=5.9855.
]

但这个 5.9855 是：

1. 先取一个 deterministic DP stopping policy；
2. 再在它的 STOP-(\Omega) distribution 上重新做 NP threshold。

它是一个**可行点**，但还不是严格证明的 constrained optimum。

更关键的是，你自己的 `SystemModel.md` 已经允许：

> deterministic policy Pareto points 之间做 episode-level randomized mixture。

而现在有两个约束：

[
P_{FA}\le0.05,
\qquad
P_D\ge0.8382.
]

因此正确的 primal constrained problem 应该直接做一个 LP：

[
\min_{\mathbf w}
\sum_k w_k B_k
]

s.t.

[
\sum_k w_kP_{FA,k}\le0.05,
]

[
\sum_k w_kP_{D,k}\ge0.8382,
]

[
\sum_k w_k=1,\qquad
w_k\ge0.
]

这里还有一个理论修正：

> **两个约束下，不应只写“两个相邻 policy 混合”。**

LP 基本解一般最多可能需要 **3 个 deterministic policies**。

# 五、2×2 实验的解释也需要稍微改一下

这一点看完完整数据后，我认为报告现在的表述有点过于简化。

报告强调：

[
8.93\rightarrow2.32\ {\rm bits}
]

说明 adjacent-only 消除了 cross-level bias。

“cross-level 会让有限 action-depth 偏向大跳步”这个判断是对的。

但：

> **adjacent-only 并不等于 solver 变好了。**

看 ((s,\eta)=(256,1))：

cross-level OPEF2：

[
B=8.9337,\qquad
\Delta J=3.448,
]

adjacent OPEF2：

[
B=2.3179,\qquad
\Delta J=24.699.
]

也就是说：

- cross-level：**看得太远/一次获取太多 → 过度通信**；
- adjacent depth-2：**只能看到极少未来信息 → 严重过早停止**。

所以 R1 真正证明的是：

[
\boxed{
\text{action-count depth 本身就是错误的 horizon 坐标}
}
]

而不是：

[
\text{adjacent-only 已解决 solver 问题}.
]

这实际上让 **resource-bounded lookahead** 的必要性更强了。

# 七、发现一个实际 baseline 小 bug：1-bit-seeded P-OTS 并没有真正冻结 1-bit 排序

这个最好在 R2 前顺手修。

当前实现：

```python
l1 = np.abs([llr_tab[i, int(zcodes[idx, i])] for i in range(N)])
order = np.argsort(-l1)
```

问题在于：

初始所有节点都是 1 bit 时：

[
llr_tab=\ell_i^{(1)}
]

没问题。

但是一旦某个 UAV 被 refinement 到 2 bit 或 4 bit：

[
llr_tab
]

取出来的已经变成：

[
\ell_i^{(2)}
\quad\text{或}\quad
\ell_i^{(4)}.
]

于是排序实际上会随着后续高精度 evidence 动态变化。

这与文档描述：

> “所有 UAV 先支付 1 bit，然后根据 paid 1-bit realized evidence 排序”

不完全一致。

所以当前的 `1bit_POTS` 实际更像：

[
\boxed{
\text{seeded + progressively re-ordered POTS}
}
]

比原计划的 fixed-after-seed baseline 更自适应。

修复很简单：从当前 nested cell 推回 level-1 ancestor：

若当前为 ((r,m))，则：

# [ m^{(1)}

\left\lfloor
\frac{m}{2^{r-1}}
\right\rfloor,
]

始终用：

[
|\ell_i^{(1)}(m_i^{(1)})|
]

排序。

或者更干净：

> 第一次 4 个 1-bit seed 全部到达后，直接冻结排序 rank。

这个修复以后，9.0274 bits 可能会变化。

不过当前 strongest fair baseline 是 B9：

[
7.5704\ {\rm bits},
]

所以这个 bug **大概率不会改变“Exact adaptive policy 优于公平 baseline”这个核心结论**。

不能写“不减”，因为“不减”在中文里正好是反方向。

代码和公式是对的，只需要修文档。
