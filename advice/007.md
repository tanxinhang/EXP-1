> **方向没有跑偏，但现在不应马上进入 CR-RBL-EB 或 CR-RBL+。**

> 而不要把“PAC rollout / LUCB / empirical Bernstein”本身当创新。

| 优先级   | 问题                                                         | 判断         |
| -------- | ------------------------------------------------------------ | ------------ |

| **P0-B** | certificate 没把 STOP 正确放入 competitor set                | 必修         |
| **P0-C** | G0 的 `Q_true` 不是 (Q_a^{\pi_b})                            | G0 需重跑    |

## 1. 当前“nested-evidence CRN”实际上没有真正发生

现在每次：

```python
rollout_return(x, h, action)
```

都会调用自己的 `_sample_latent()`，而不同 action 是按 RNG 顺序分别采样的。

因此实际是：

[
W_a^{(m)}\neq W_b^{(m)}
]

而真正的 CRN 应该是：

[
\boxed{
W^{(m)}
\longrightarrow
{G_a(W^{(m)}):a\in\mathcal A}
}
]

即同一个 latent world 同时评价候选动作。

当前实现的 nested projection 本身是合理的，但没有把 **world object 提升到 action 之外**。所以现在还不能宣称：

[
\operatorname{Var}(G_a-G_b)
]

已经因为 paired CRN 显著降低。`rbl_cr.py` 的注释宣称 candidate actions share the same latent realization，但执行路径并非如此。

而且这点在 2026 年尤其要谨慎：今年已有专门研究 **Common Random Numbers for simulation-based planning with rollouts** 的工作，并证明 rollout 中 CRN 可以降低 relative-utility variance。也就是说，**CRN 本身不能作为创新点**；你的特色应该是 *nested evidence induced coupling + variable-cost evidence DAG + certified acquisition*。([arXiv](https://arxiv.org/abs/2605.04732?utm_source=chatgpt.com))

## 2. 当前 certificate 对 STOP 的处理有数学漏洞

目前 action certificate 大致是：

[
U_{\hat a}
\le
\min_{b\ne\hat a}L_b+\epsilon.
]

但是代码检查候选 reporting actions 时，没有同时要求：

[
\boxed{
U_{\hat a}\le R_{\rm stop}(x)+\epsilon
}
]

其中 STOP 是一个**精确已知的竞争动作**。

因此正确 competitor set 应该是：

# [ \mathcal A^+(x)

\mathcal A(x)\cup{\mathrm{STOP}}.
]

对于 reporting action (\hat a)：

[
\boxed{
U_{\hat a}
\le
\min
\left{
R_{\rm stop},
\min_{b\neq\hat a}L_b
\right}
+\epsilon .
}
]

对于 STOP：

[
\boxed{
R_{\rm stop}
\le
\min_bL_b+\epsilon .
}
]

否则存在一种情况：

[
Q_{\hat a}

> 

R_{\rm stop}+\epsilon
]

但 (\hat a) 仍可能被标记 `certified=True`。这是 P0，应先修。

# 二、G0/G1/G3 目前需要重新定标

## G0：现在比较错了 oracle

G0 里：

```python
Qs = exact_qa(...)
Q_true = Qs[target_a]
```

而 `exact_qa()` 的 continuation 是：

[
V^\star(x')
]

因此这里得到的是：

[
Q_a^\star.
]

但 Monte Carlo rollout 估的是：

[
Q_a^{\pi_b}.
]

所以实际上在检查：

[
\hat Q_a^{\pi_b}
\quad\text{是否覆盖}\quad
Q_a^\star,
]

不是理论要求的：

[
\hat Q_a^{\pi_b}
\quad\text{是否覆盖}\quad
Q_a^{\pi_b}.
]

这意味着目前的“100% coverage”不能作为 CR-RBL-H certificate 实现正确性的证据。

正确方式直接使用已经写好的：

```python
exact_qa_pi_b(...)
```

作为 G0 oracle。

## G1/G3：STOP oracle 也错位了

代码现在用：

```python
R0_pi = base_policy_value(cr, x, H)
```

来和 candidate (Q_a^{\pi_b}) 比较。

但 STOP 的值应该是：

# [ \boxed{ R_{\rm stop}(x)

\min{
C_{01}p(x),
C_{10}[1-p(x)]
}.
}
]

`base_policy_value(x,H)` 是“从当前状态继续执行 (\pi_b)”的价值，不是 STOP。

所以真正的：

# [ a_{\pi_b}^\star(x)

\arg\min
\left{
R_{\rm stop}(x),
Q_a^{\pi_b}(x)
\right}.
]

G1 的 8.8% match、G3 的 violation 统计都应在这个修复后重跑。

# 三、G5 有一个很明显的 resource semantics 问题

这是本轮我认为最需要修的工程/数学接口之一。

当前：

```python
cr8.plan(x_int[e], H, ...)
```

在每一次 receding decision 都重新传完整 (H)。

但执行后：

```python
cost[e] += ...
```

下一次没有：

```python
h_rem = H - cost[e]
```

于是报告出现：

[
H=48,
\qquad
E[B]=177.4.
]

这直接说明 (H) 没有作为 episode hard budget 执行。

这里必须明确选择一种语义。

如果 (H) 是 **hard communication budget**，那么：

# [ h_t

H-C_t,
]

且必须 pathwise 保证：

[
\boxed{
C_T\le H.
}
]

如果 (H) 只是 **MPC/RBL planning horizon**，那也可以，但必须改名：

[
H_{\rm plan},
]

不能再把它描述成 resource budget。

我更建议当前 B0 保持第一种，因为 `SparsePlanner` 从定义上就是 resource-bounded Bellman planner，而且 conservative lattice 也正是为 hard feasibility 服务。`sparse.py` 当前 `ceil(c/\Delta c)` / `floor(h/\Delta c)` 的方向是正确的。

# 四、B0.1a 的 (b^*\approx8) 很有价值，但理论表述还能再升级

这个结果我建议保留，而且它事实上可能比 CR-RBL 本身更有论文辨识度。

但是现在应该把：

> critical feedback-granularity threshold (b^*\approx8)

改成：

[
\boxed{
b^\star(x_0)\approx8
}
]

即**root-state critical setup-cost threshold**。

原因很清楚：reachable-state sweep 中：

# [ E[\Delta Q]

-14.26,-12.66,-11.10,-8.14,-2.64
]

直到 (b=32) 仍然为负；真正 (b\approx8) 穿零的是 root-state 的 (g(b))。

这并不是坏事，反而可以把理论提升一层。

你已经证明：

# [ g_x(b)

\mathbb E[
\min{Y_x,b}
],
]

其中：

[
Y_x=D(x')-\Delta_2.
]

于是可以直接给出一个很漂亮的性质。

对固定 (x)，(g_x(b))：

[
\boxed{
\text{monotone nondecreasing and concave in }b.
}
]

因为对于固定 (Y)：

[
b\mapsto\min(Y,b)
]

本身就是非减凹函数，期望保留这两个性质。

而在无原子点：

# [ \boxed{ g_x'(b)

\Pr(Y_x>b).
}
]

于是可以定义：

# [ \boxed{ b^\star(x)

\inf
{b:g_x(b)\ge0}.
}
]

这样论文里的“critical threshold”就从一个数值现象升级成：

> **state-dependent feedback-granularity phase boundary**。

通信意义非常明确：

[
b_h<b^\star(x)
]

时，小 packet progressive refinement 可以抵消额外 transaction；

而：

[
b_h>b^\star(x)
]

时，per-transaction setup/header 开销占主导，应该减少反馈次数、提高单次 packet granularity。

这个理论比“边际收益”老套路明显更强，因为它直接给出了 **packetization regime transition**。

# 五、因此下一步不要直接做普通 CR-RBL-EB，而应做“真正的 coupled CR-RBL”

Empirical-Bernstein CS 是正确工具。bounded-mean 的 time-uniform empirical-Bernstein / betting confidence sequence 已有成熟理论，而且天然允许 arbitrary stopping time。([OUP Academic](https://academic.oup.com/jrsssb/article/86/1/1/7043257?utm_source=chatgpt.com))

但仅仅把：

[
\text{Hoeffding}
\rightarrow
\text{Empirical Bernstein}
]

创新性很弱。

固定置信 BAI、structured BAI 也已经是成熟领域，最近工作仍在继续研究怎样利用 arm structure 降低样本复杂度。([Proceedings of Machine Learning Research](https://proceedings.mlr.press/v258/chen25b.html?utm_source=chatgpt.com))

因此我建议下一版不是简单叫“CR-RBL-EB”，而在算法本质上做下面这个变化：

[
\boxed{
\text{arm-wise estimation}
\rightarrow
\text{paired action-difference certification}
}
]

生成一次：

# [ W_m

(H_m,M_{1,m}^{(8)},\ldots,M_{N,m}^{(8)})
\mid x.
]

然后从同一个 (W_m) 计算：

[
G_{a,m},
\qquad
G_{b,m}.
]

直接构造：

# [ \boxed{ Z_m^{a,b}

G_{a,m}-G_{b,m}.
}
]

估计的不是两个大数：

[
Q_a,\quad Q_b,
]

而是直接估：

# [ \Delta_{a,b}

Q_a-Q_b.
]

理论上：

# [ E[Z^{a,b}]

Q_a^{\pi_b}-Q_b^{\pi_b}.
]

如果 nested coupling 有效，应出现：

[
\operatorname{Var}(Z^{a,b})
\ll
\operatorname{Var}(G_a)
+
\operatorname{Var}(G_b).
]

这才真正把你的 **nested-evidence DAG** 转化成 sample-efficiency advantage。

# 六、再加一个非常值得做的改进：不要 uncertified 就执行 empirical best

现在：

```text
max_samples exhausted
→ certified=False
→ execute empirical best
```

这会让 CR-RBL 在最不确定的时候执行最不可靠的 action。

而 G1 只有 8.8% action match，本身已经说明这种 fallback 风险很大。

更合理的是：

[
\boxed{
\text{uncertified}
\Rightarrow
\text{fallback to base policy}.
}
]

甚至可以进一步变成 **certified policy improvement**：

对 base action (a_b) 和 candidate (a) 构造 paired difference：

# [ D_a

## Q_a^{\pi_b}

Q_{a_b}^{\pi_b}.
]

只有当：

[
\boxed{
U(D_a)<0
}
]

时才 override base。

否则：

[
a=a_b.
]

这样得到一个非常漂亮的性质：

> CR-RBL 不再试图每个状态都“猜最优动作”，而是只在统计证据足够时偏离可靠基线。

这与通信系统尤其契合，因为你最终需要的是：

[
\text{低通信成本下的可靠 improvement},
]

不是“Monte-Carlo planner 的 action accuracy 好看”。

# 七、Base policy 也建议换掉 SNRDirectBase

目前：

[
\pi_b=\text{SNR strongest Direct-8}
]

工程上简单，但与优化目标：

[
c_a+E[R_{\rm stop}(x')]
]

并不完全一致。

我建议加入一个很轻的 **one-step conditional-VoI base**：

# [ \boxed{ a_b(x)

\arg\min_a
\left[
c_a+
E[R_{\rm stop}(X')\mid x,a]
\right].
}
]

如果：

[
\min_a
\left[
c_a+
E[R_{\rm stop}(X')]
\right]
\ge
R_{\rm stop}(x),
]

则 STOP。

它有几个好处：

不增加学习模型，不引入神经网络，不违背分布式/通信物理；直接包含 (b_h+\Delta r)；直接利用你已经建立的 conditional VoI；并且通常比纯 SNR order 更接近 Bellman objective。

它不是论文创新，而是一个**更合格的 rollout base**。

# 八、CR-RBL+ 的 Bellman sandwich 思路是对的，但 `006.md` 中有一个不等式要改

`006.md` 写：

[
V_{\rm genie}
\le
V^\star
\le
V^{\pi_b}
\le
R_{\rm stop}.
]

最后一个：

[
V^{\pi_b}\le R_{\rm stop}
]

对于任意 (\pi_b) **不成立**。

base policy 完全可能报告过度，使：

[
V^{\pi_b}>R_{\rm stop}.
]

因此正确的是：

[
\boxed{
V_{\rm genie}
\le
V^\star
\le
\min
{
V^{\pi_b},
R_{\rm stop}
}.
}
]

前两层仍然完全成立。

实际上这反而能推导出比原计划更漂亮的 CR-RBL+。

定义 leaf：

[
L_0(x)=V_{\rm genie}(x),
]

# [ U_0(x)

\min
{
R_{\rm stop}(x),
V^{\pi_b}(x)
}.
]

于是：

[
L_0(x)
\le
V^\star(x)
\le
U_0(x).
]

对 Bellman operator：

# [ (\mathcal TV)(x,h)

\min
\left{
R_{\rm stop}(x),
\min_a
[c_a+E V(x',h-c_a)]
\right},
]

由于 (\mathcal T) 单调：

[
L_k=\mathcal T^kL_0,
\qquad
U_k=\mathcal T^kU_0
]

满足：

[
\boxed{
L_k
\le
V^\star
\le
U_k.
}
]

而 nested-evidence DAG 是有限 acyclic DAG，所以随着 backup depth 增大：

[
U_k-L_k
]

原则上会持续收紧，最终在完整深度闭合到 exact DP。

这比原先简单的：

[
\epsilon_{\rm stat}+\epsilon_{\rm tail}
]

更有理论味道。

# 九、这可以形成真正论文级的 CR-RBL+ certificate

对 action (a)：

# [ \underline Q_a

c_a+
E[L_k(X')],
]

# [ \overline Q_a

c_a+
E[U_k(X')].
]

如果：

[
\boxed{
\overline Q_{\hat a}
\le
\min_{b\ne\hat a}\underline Q_b+\epsilon,
}

则直接有：

[
\boxed{
Q^\star_{\hat a}
\le
\min_b Q_b^\star+\epsilon.
}

这已经不再是：

[
Q^{\pi_b}
]

certificate，而是真正相对：

[
V^\star.
]

如果 leaf bounds 或 expectation 用 Monte Carlo CS，再把 statistical confidence 合进去：

[
\Pr
\left(
Q^\star_{\hat a}
\le
Q^\star_{a^\star}+\epsilon
\right)
\ge1-\delta.
]

我认为这一层才真正配得上：

> **confidence-certified approximate planning over a nested evidence DAG**。

# 十二、G3 的统计 Gate 也要更严格

现在：

[
34\text{ certified decisions},
\qquad
0\text{ violations}.
]

直接写：

> empirical violation rate (=0\le0.05) → PASS

证据不够。

如果 34 次里 0 次 violation，95% 单侧 binomial 上界仍大约在 0.08–0.10 量级，不能排除真实 violation probability (>0.05)。

所以正式 Gate 应写：

[
\boxed{
U_{95%}(p_{\rm violation})
\le\delta .
}
]

若始终 0 violation，大致至少需要 **约 59 个 certified samples** 才能让简单 exact one-sided upper bound 降到 0.05 以下。

而且建议同时报告：

[
\text{certification rate},
]

因为“0 violation，但只认证极少数状态”不是一个强 planner。

# 十三、最终论文创新建议也稍微调整

现在：

> Confidence-certified, feedback-granularity-aware evidence acquisition over a variable-cost nested-evidence DAG

方向是对的。

但我建议最终把贡献分成三层，而不是把 CR-RBL 算法名本身放第一位：

**理论层：**

[
\boxed{
\text{State-dependent Critical Feedback-Granularity Threshold}
}
]

证明：

[
g_x(b)=E[\min(Y_x,b)]
]

的单调性、凹性以及 (b^\star(x)) 的存在条件，解释 setup overhead 导致 progressive/direct packetization regime switch。

**算法层：**

[
\boxed{
\text{Coupled Latent-Evidence Certified Acquisition}
}
]

利用 nested quantizer 的 pathwise coupling，直接构造 paired action-difference CS，而不是普通 independent rollout。

**认证层：**

[
\boxed{
\text{Bellman-Sandwich Certified Approximate Planning}
}
]

利用：

[
L_k
\le
V^\star
\le
U_k
]

把 certificate 从：

[
Q^{\pi_b}
]

提升为：

[
Q^\star.
]

这样 reviewers 很难把文章概括成：

> “把 empirical Bernstein/LUCB 用到了 UAV detection”。

因为 empirical-Bernstein CS 本身已有成熟统计理论，fixed-confidence BAI 也已有大量基础；真正属于你的部分是 **通信反馈粒度结构如何改变最优证据获取，以及如何利用 nested evidence coupling 对这种策略做认证**。([OUP Academic](https://academic.oup.com/jrsssb/article/86/1/1/7043257?utm_source=chatgpt.com))

# 十四、最重要的停止规则仍然不变

现在 B0.1a 的最强现实 baseline 其实已经很清楚：

[
\text{Direct8-Ordered}:
P_D\approx0.886,\quad E[B]\approx110.5,
]

而 CR-RBL 当前演示：

[
P_D\approx0.705,\quad E[B]\approx177,
]

甚至还存在 hard-budget 语义问题。

因此现阶段**绝对不要进入 fading/B1 去寻找优势**。

先完成：

\rightarrow
\text{paired CRN}
\rightarrow
\text{EB difference CS}
\rightarrow
\text{safe fallback}
\rightarrow
\text{matched QoS}.

[

\begin{aligned}
&P_{FA}^{CR}\le\alpha,\qquad
P_{MD}^{CR}\le\beta,\
&P_{FA}^{D8}\le\alpha,\qquad
P_{MD}^{D8}\le\beta,\

E[B]*{CR}
<
E[B]*{D8}
\text{ with CI?}
\end{aligned}

如果答案仍然是否定的，就不要继续往算法里塞东西。

此时最好的论文反而是：

> **feedback granularity 存在明确的 phase transition，但在当前 sensing regime / setup cost 区域中，optimal policy 落在 direct-packetization regime。**

这仍然是一个数学上诚实且有价值的结果。

**所以我给当前工程的明确决策是：先做 `B0.3a`，暂缓 CR-RBL+；`B0.4` 不做普通 EB 替换，而直接做“true paired latent-world + difference-CS + certified fallback”。在这一版证明有明显 sample-efficiency/action-quality 改善之后，再进入 Bellman sandwich。** 这是目前最收敛、理论最稳，也最有可能最终形成 TSP/TWC 级叙事的路线。
