## 3. Exhaustive 证书发现并修复一个真实 bug（d2=0 退化）

4-bit N=4 exhaustive 检查立刻暴露 `run_mvsc021.py` 的 **d2=0 退化 bug**：
当 r_next == r_max（如 4-bit r=2→4、8-bit r=4→8），probe 与 direct 是**同一
动作**，但旧代码 C 区 E_R 保持 0（ref 模板为空），导致 gap 假性 E[min(R1,16)]
而真实 Q_prog−Q_dir 为负（可差上百 bits）——prune 决策与恒等式门在退化状态
失真。修复（与 phase_boundary.py 同语义）：d2==0 时 E_R=R1、D=0、Y=0 ⇒
Q_prog=Q_dir、gap=0。修复后 exhaustive 0 矛盾；T42 回归锁定；C2.1 的 8-bit
263 检查不受影响（reachable 中无退化状态），Gate D1 1.88% PASS 不变。

A 区在 N=4/H=96 下经 exhaustive BFS 确认**数学上不可达**（正确理由：单 UAV
4-bit ladder 可达花费 ∈ {17,18,20,34,36,52}，3-UAV 总花费集合中 (76,79] 为空
——剩余 h∈[17,20) 无可行组合；007 审计修正了此前 "3×20=60" 的错误论证），
A 区安全由 N=1 synthetic 反例 + "A 区绝不剪"断言保证（与 005 §十 观察一致）。
