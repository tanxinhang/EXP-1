# 三、P1：当前所谓 QoS-“dual price”存在一个 prior normalization 语义问题

代码定义：

[
\lambda_M=\rho,\qquad
\lambda_F=\rho e^\eta,
]

以及

# [ R_{\rho,\eta}(x)

\rho\min
{
p_x,e^\eta(1-p_x)
}.
]

如果你的理论问题真的是：

[
\min_\pi E[B]
]

s.t.

[
P_{FA}\le\alpha,\qquad
P_{MD}\le\beta,
]

Lagrangian 为：

[
E[B]
+
\lambda_F P_{FA}
+
\lambda_M P_{MD},
]

注意这里 (P_{FA})、(P_{MD}) 是**conditional error probabilities**。

则在 posterior (p_x=P(H_1|x)) 下，terminal conditional risk 应为：

# [ \boxed{ R_\lambda(x)

\min
\left{
\frac{\lambda_M}{\pi_1}p_x,
\frac{\lambda_F}{\pi_0}(1-p_x)
\right}.
}
]

原因是：

# [ P_{MD}

\frac{P(\hat H=0,H_1)}{\pi_1}.
]

你旧的 `SparsePlanner` 实际上正是这么做的：

```python
self.C01 = mu_M / pi[1]
self.C10 = mu_F / pi[0]
```

而当前 G2 直接使用：

[
\rho p,\qquad \rho e^\eta(1-p).
]

当前模型：

[
\pi_0=\pi_1=0.5,
]

所以幸运的是，两边只共同少了 factor 2：

[
R_{\rm exact}=2R_{\rm current}.
]

这等价于把 (\rho) 重新缩放一倍。

因此：

### 不会推翻 G2 数值结果

因为 (\rho) 本来就是 calibration grid 参数。

但它意味着：

> 当前 `ρ` 严格说不是条件错误率约束的原始 Lagrange multiplier，而是吸收了 prior 的 effective terminal-risk scale。

所以建议二选一：

**方案 A，最省事：不改实验，只改理论定义。**

定义：

# [ \bar\lambda_M

# \frac{\lambda_M}{\pi_1}, \qquad \bar\lambda_F

\frac{\lambda_F}{\pi_0},
]

然后参数化：

[
\bar\lambda_M=\rho,\qquad
\bar\lambda_F=\rho e^\eta.
]

这样当前代码完全正确。

这是我更推荐的方案。

不要再动 G2 数字。

# 四、P1：sensitivity runner 有真实逻辑 bug，且 README 与 FULL report 互相矛盾

这部分值得修。

当前 sensitivity 代码：

```python
th_min = min(tbl, key=lambda th: (tbl[th]["eb"], th[0], th[1]))
```

也就是：

> 在**全部参数**里直接找最小 (E[B])。

这样自然会找到那种：

> 一开始直接 STOP，0 bit，但 P_MD≈1

两个描述显然不能同时叫：

> “Ê_cal[B] 最小候选”。

### 真正应该审查的问题不是“全局最小 cost candidate”

而应该是：

# [ \boxed{ \mathcal C_m

{
\theta:
\widehat E[B_\theta]
<
\widehat E[B_{\hat\theta_m}]
}.
}

也就是：

> **所有比当前 θ̂ 更便宜的 challenger。**

然后分成：

- UNCERTAIN；

[
\boxed{
\exists\theta\in\mathcal C_m:
\theta=\mathrm{UNCERTAIN}.
}
]

FG 的 `(128,0.8)` 就属于应该重点报告的候选，因为：

[
U_{95}(P_{FA})=0.1229
]

只比：

[
0.12
]

高一点。

所以建议 sensitivity 改成：

```text
for all theta with Ecal[B(theta)] < Ecal[B(theta_hat)]:
    report QoS state
```

而不是找一个 absolute minimum。

# 九、P1：`gross forced-action cost << 12.31` 不能作为 causal upper bound

这里又有一个逻辑细节。

报告现在已经正确说：

> gross forced-action cost 不是 causal extra cost。

很好。

但下一句又说：

> 即使把 1.485 bit/episode 全视为 leakage bias，也远低于 12.31，因此 G1 不可能主要由 leakage 解释。

这个推导其实不严格。

1. 改变 posterior；
2. 改变后续 UAV selection；
3. 改变 stopping time；
4. 改变后续 transaction 数量。

因此 causal impact：

[
\Delta B_{\rm causal}
]

不保证满足：

[
|\Delta B_{\rm causal}|
\le
B_{\rm forced,gross}.
]

它可能产生后续连锁效应。

所以 `1.485 bit` 只能说明：

> immediate forced expenditure 很小。

不能作为总 leakage bias 的数学上界。

幸运的是你根本不需要这个论证，因为 **G1r-B 的 S_ref experiment 已经真正解决了 causal fairness 问题**：

[
U_{95}<0
]

仍成立。

所以建议把 robustness statement 降级为：

> The immediate communication expenditure directly associated with forced-continuation states is small; the stronger causal robustness evidence is provided by G1r-B, where the leakage mechanism is removed by construction.

这就非常严谨。

24\text{ bits}
