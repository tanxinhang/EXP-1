## 1. P0：canonical orientation 仍有第二层 bug——样本方向修了，但 support range 没完全修

你已经正确修了：

[
Z=G_a-G_b
]

在 candidate 切换后必须转换成固定 canonical 方向。`feed()` 当前会根据 canonical key 翻转符号，这部分是对的。

但是 `range_ab` 的建立仍然是：

```python
a, b = actions[ia], actions[ib]
range_ab[pair_key(a, b)] = (
    l_a - u_b,
    u_a - l_b
)
```

问题是 `pair_key(a,b)` 可能把顺序交换，但 support 没跟着交换。

例如动作枚举为：

[
a=(7,1),\qquad b=(6,1),
]

canonical key 是：

[
((6,1),(7,1)).
]

CS 真正收到的是：

[
G_{6,1}-G_{7,1},
]

但 `range_ab` 却可能仍然保存：

[
[l_7-u_6,;u_7-l_6],
]

这是反方向 (G_7-G_6) 的 support。

这个问题在 N=4 默认 `i=0,1,2,3` 升序动作集里很难触发，所以 G0/T23 没抓到；但 G4 明确使用：

```python
top_k_uavs=[7,6,5,4]
```

此时 action list 本身就是非 canonical 顺序。

这会破坏 PairCS 所依赖的：

[
X_t=
\frac{Z_t-\ell}{u-\ell}\in[0,1].
]

### 正确修法

不要先按原 `(a,b)` 算 range，再挂到 canonical key 上。应先 canonicalize：

[
(c_0,c_1)=\operatorname{sort}_{key}(a,b),
]

然后严格计算：

# [ \boxed{ [\ell_{01},u_{01}]

[l_{c_0}-u_{c_1},
u_{c_0}-l_{c_1}]
}.
]

并在 `PairCS.update()` 增加硬 invariant：

```python
x = (z - lo) / (hi - lo)
assert -tol <= x <= 1 + tol
```

再新增一个 regression，故意使用：

```text
top_k_uavs=[7,6,5,4]
```

以及不同 precision 的 pair，验证 canonical sample 和 canonical support 同向。

现有 T23 使用手写对称区间：

[
[-400,400],
]

因此只能抓“sign mixing”，抓不到“非对称 support orientation”。

# 2. P0：501 点 grid inversion 目前不是严格的 continuum confidence sequence

这是统计上更需要重视的一点。

对每一个**固定** (\mu)，你现在的 wealth process：

# [ K_n(\mu)

\prod_t
[1+\lambda_t(\mu)(X_t-\mu)]
]

在 (\lambda_t(\mu)) predictable 且 factor 非负时，可以用 Ville 不等式构造 time-uniform test。这个核心思路是正确的，也符合 Waudby-Smith–Ramdas 的 betting framework。WSR 的正式工作确实构造了 arbitrary-stopping-valid bounded-mean CS，同时区分了 closed-form empirical-Bernstein CS 和 non-closed-form betting CS。([OUP Academic](https://academic.oup.com/jrsssb/article/86/1/1/7043257?utm_source=chatgpt.com))

但是当前实现不是对连续：

[
\mu\in[0,1]
]

真正求：

[
{\mu:K_n(\mu)<1/\alpha},
]

而是只在：

```python
np.linspace(0, 1, 501)
```

上计算，然后把 surviving grid points 的 min/max 各扩一个 grid step。

这一步**没有自动继承 Ville 的 continuum coverage guarantee**。

原因是理论保证针对真实：

[
\mu^\star,
]

而 (\mu^\star) 一般不落在这 501 个点上。除非额外证明：

1. acceptance set 对 (\mu) 必定是一个 interval；
2. wealth 关于 (\mu) 具有足够的单调/凸结构；
3. 一格扩张必然覆盖任意 off-grid accepted (\mu)；

否则：

> “grid inversion + expand one step”

只是 numerical approximation，不是严格 theorem。

G0 的：

[
1.000
]

empirical anytime coverage 是很好的 sanity check，但不能替代数学保证。

### 最稳妥的处理

我建议 B0.4r 不继续自己证明这个 custom grid。

把**正式 certificate path**换成 WSR 已证明的 predictable plug-in empirical-Bernstein CS，直接产生连续区间，不做 grid inversion。

当前 betting-grid 版本可以保留为：

> experimental tighter betting CS

但不要承担论文主 certificate。

这样最干净：

[
\boxed{
\text{theorem-backed PrPl-EB CS}
\rightarrow
\text{formal certificate}
}
]

而：

[
\text{custom betting inversion}
\rightarrow
\text{ablation}.
]

这也避免 reviewer 追问“为什么 501？换成 301/1001 会不会影响 coverage？”

# 3. “WSR-2023 EB-CS”这个名称建议稍微收紧

当前 `PairCS` 的下注规则本质上是你自己选的 predictable bet：

# [ \lambda_t(\mu)

\operatorname{clip}
\left[
\frac{4}{\hat\sigma_{t-1}^2+\epsilon}
(\hat\mu_{t-1}-\mu)
\right].
]

这在满足 nonnegative-factor 条件时可以是**合法 betting martingale**，但它并不是简单照搬 WSR 的标准 predictable plug-in EB closed-form formula。

因此目前更准确的名字是：

> **WSR-style variance-adaptive betting CS**

而不是直接说：

> **WSR-2023 empirical-Bernstein CS**

除非 B0.4r 直接换成论文的 theorem-backed PrPl-EB construction。

这主要是论文归因严谨性问题，不是当前 pairwise idea 的错误。

# 4. G1 的“27×”是真实观察，但因果归因目前混了三件事

B0.4 同时改变了：

[
\text{arm-wise}
\rightarrow
\text{pair difference},
]

[
\text{Hoeffding}
\rightarrow
\text{betting CS},
]

以及：

[
\text{full pairing}
\rightarrow
\text{candidate–challenger}.
]

所以：

[
0.025
\rightarrow0.675
]

不能全部解释成：

> “EB-CS + (\kappa\simeq13) 导致 27×”。

建议正式做一个很小的三格/四格消融：

| 方法       | pair statistic | shared world | CS                 | sampling   |
| ---------- | -------------- | ------------ | ------------------ | ---------- |
| H0         | arm-wise       | shared       | Hoeffding          | full       |
| H1         | **difference** | shared       | **pair-Hoeffding** | challenger |
| E1         | difference     | shared       | **EB/PrPl**        | challenger |
| E0（可选） | difference     | independent  | EB/PrPl            | challenger |

这样：

[
H0\rightarrow H1
]

告诉你“pairwise statistic + sparse pair sampling”的收益；

[
H1\rightarrow E1
]

才是真正的 variance-adaptive CS 收益；

[
E0\rightarrow E1
]

才是 nested CRN coupling 的收益。

这会让 (\kappa\approx13) 的论文论证非常扎实。

# 6. G4 的 scaling 结论现在说得过头了

当前报告最后写：

> “总 rollout 与 (|A|) 无关，UAV 数增加不放大规划成本。”

严格来说不成立。

正确的是：

# [ \boxed{ \text{rollouts per sampled world}

O(1)
}
]

从：

[
|A|
]

下降到：

[
1\sim2.
]

但是总 sample complexity 仍然依赖 (|A|)。

首先：

[
P={|\mathcal A^+|\choose2}
]

且：

[
\alpha_{ab}=\delta/P,
]

因此置信宽度至少带有：

# [ \log P

O(\log |A|).
]

其次 challenger 搜索当前：

```python
max(others, ...)
```

每轮是：

[
O(|A|).
]

而 pair-CS 存储最坏可以达到：

[
O(|A|^2).
]

此外更多 arms 通常需要更多 worlds 才能把全部潜在 challenger 排除掉。

所以论文正确表述应改为：

> **per-world rollout complexity is reduced from (O(|A|)) to (O(1)); total certification complexity still depends on the action-set size through exploration and simultaneous-confidence allocation.**

这依然是很好的 scalability 结果，只是不能写成“与 UAV 数无关”。

[

[

]

时才切换。

这与下一步 certified policy improvement 更一致。

[

不会因为 grid certificate 问题自动失效，因为这些 gap 是事后用 exact (Q^{\pi_b}) 评价的。

**2 rollouts/world 是真实的结构性改进。** 只是应表述为 per-world，而不是 total-complexity independent of (|A|)。
