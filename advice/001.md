# 二、当前最大的理论问题：优化和评价其实不是同一个问题

`SystemModel.md` 定义的是

[
\min_\pi \mathbb E[C_\pi]
]

subject to

[
P_M^\pi\le \beta_M,\qquad P_{FA}^\pi\le\alpha ,
]

并引入两个乘子

[
\mu_M,\qquad \mu_F.
]

终端风险是

[
R_0=C_{01}p,\qquad
R_1=C_{10}(1-p),
]

其中

[
C_{01}=\frac{\mu_M}{\pi_1},\qquad
C_{10}=\frac{\mu_F}{\pi_0}.
]

理论文档本身还明确说应该 sweep ((\mu_M,\mu_F))。

但实际实现是：

```python
dp.solve(mu, mu)
o1.solve(mu, mu)
o2.solve(mu, mu, V1)
```

即始终

[
\boxed{\mu_M=\mu_F}.
]

在 prior=0.5/0.5 时，这意味着 DP 内部的终端 decision threshold 实际对应：

[
p^\star=0.5,\qquad \Omega^\star=0 .
]

也就是说，它优化的是一个**对漏检和虚警近似对称的 Bayes decision**。

但策略停止以后，`mc.evaluate()` 又完全不使用这个终端 Bayes decision，而是：

> 根据最终的 (\Omega)，重新在 Monte Carlo 样本上寻找一个阈值，使 (P_{FA}=0.05)。

因此现在实际上是：

[
\boxed{
\text{用 Bayes-error criterion 决定“收集哪些信息”}
}
]

然后：

[
\boxed{
\text{用另一个 NP criterion 决定“最终是否检测”}
}
]

这两个不是同一个优化问题。

这也是我认为当前结果最需要纠偏的地方。

# 三、μ→∞ 的解释目前存在一个数学错误

报告目前解释：

> 后验偏向一侧后，弱 UAV 的 probe 可能“增加期望 min-risk”，所以即使 μ→∞ 也不值得查询。

严格来说，这个表述是不成立的。

终端 Bayes risk 是

# [ R_{\rm stop}(p)

\min
\left{
C_{01}p,,
C_{10}(1-p)
\right}.
]

它是 (p) 的**凹函数**。

而 posterior 满足 martingale：

[
\mathbb E[p'|p]=p.
]

因此 Jensen 不等式直接给出

[
\boxed{
\mathbb E[
R_{\rm stop}(p')
\mid p
]
\le
R_{\rm stop}(p)
}.
]

换句话说：

> **额外信息本身不会增加 optimal expected Bayes risk。**

它可能只有**零价值**，但不会具有“负信息价值”。

真正可能发生的是

[
c_a+
\mathbb E[R_{\rm stop}(p')]

> 

R_{\rm stop}(p),
]

这里之所以停止，是因为有正通信成本 (c_a)，不是因为 evidence 本身有害。

更重要的是，当 (\mu\rightarrow\infty) 时，如果某个 observation 存在严格正的 Bayes-risk reduction，那么 risk 部分会被 μ 放大，最终必然压过有限的 bit cost。

因此 μ→∞ 还停止的状态主要应解释为：

[
\boxed{
\text{该剩余信息对于当前 Bayes decision threshold 的价值恰好为 0}
}
]

而不是“信息负收益”。

为什么这些信息在你最后的 `P_FA=0.05` ROC 上又可能有用？

因为 DP 判断信息价值的时候 decision boundary 在大约

[
\Omega=0,
]

而你最后 NP evaluation 使用的是另一个 threshold。

所以：

> **对 Ω=0 的 Bayes 决策不再有价值的信息，仍然可能改变 Ω 在 NP threshold 附近的排序。**

这正好可以解释目前所谓的“DP μ→∞ 检测上限”。

因此：

[
\boxed{
\text{当前 μ→∞ ceiling 首先是 criterion mismatch 的症状，不能先解释成 O-PEF 的固有局限。}
}
]

# 四、现在的 50.2% “solver gap”其实不能成立

报告在 (\mu=256) 给出：

| 方法   | E[B]   | PD     |
| ------ | ------ | ------ |
| DP     | 5.4157 | 0.8118 |
| OPEF-1 | 5.0223 | 0.7026 |
| OPEF-2 | 8.1320 | 0.8189 |
| OPEF-3 | 7.9521 | 0.8263 |

然后定义

[
\frac{8.1320-5.4157}{5.4157}
=50.2%.
]

但注意：

[
P_D^{\rm OPEF2}=0.8189

> 

0.8118=P_D^{DP}.
]

两个策略的性能根本没有 matched。

更明显的是 OPEF-1：

[
E[B]*{\rm OPEF1}
<
E[B]*{\rm DP}
]

所以当前 gap 是 **−7.3%**。

难道 OPEF-1 比 Exact DP 更优？

当然不是。只是因为 OPEF-1 过早停止，检测性能掉到了 0.7026。

这恰好证明：

[
\boxed{
\text{“同 μ 比通信成本”不是 solver quality metric。}
}
]

真正应该比较的是 DP 实际优化的 Lagrangian objective：

# [ \boxed{ J_\mu(\pi)

E[B_\pi]
+
\mu_M P_M^\pi
+
\mu_F P_{FA}^\pi
}
]

对于同一个 ((\mu_M,\mu_F))，Exact DP 必须满足：

[
\boxed{
J_\mu(\pi_{\rm DP})
\le
J_\mu(\pi)
}
]

对于任何 OPEF-1/2/3。

因此正确 G2 应改为：

# [ \Delta J_k

## J(\pi_{\rm OPEF-k})

J(\pi_{\rm DP})
\ge0.
]

而最终论文真正关心的 gap 再定义成：

# [ \boxed{ Gap_{\rm QoS}

\frac{
E[B]*{\rm OPEF}-E[B]*{\rm DP}
}{
E[B]_{\rm DP}
}
}
]

但前提是二者都满足同样：

[
P_{FA}\le0.05,
\qquad
P_D\ge P_{D,\max}-\epsilon_D.
]

所以当前：

> **G2 不应该标记 FAIL，而应该暂时标记 INVALID / REOPEN。**

# 五、还有一个很关键的 solver 结构问题：0→4 本来就不该出现在 MVS-A

这是这轮代码审计中另一个很关键的发现。

MVS-A 明确规定：

[
b_h=0,
\qquad
p_{\rm succ}=1,
]

成本只有 incremental payload bits。

但 `StateSpace` 现在允许：

[
0\to1,\quad0\to2,\quad0\to4,
]

以及：

[
1\to2,\quad1\to4,\quad2\to4.
]

在 MVS-A 条件下，其实可以证明：

[
\boxed{
\text{cross-level jump 被 adjacent progressive refinement 弱支配。}
}
]

例如比较：

[
0\rightarrow4
]

和

[
0\rightarrow1\rightarrow2\rightarrow4.
]

两者如果最终都到 4 bit，总 payload cost 都是：

[
4\ {\rm bit}.
]

但是 sequential 方案在 1 bit、2 bit 之后多出了“可以停止/改查其他 UAV”的选择权。

它完全可以忽略中间 evidence，一直走到 4 bit，从而严格复现 `0→4`；

同时又可以利用中间 evidence 提前停止。

因此：

[
\boxed{
V_{\rm sequential}
\le
V_{0\to4}.
}
]

所以在 **header=0、perfect channel 的 MVS-A** 中，跨级动作在 Exact DP 里是冗余的。

但是对 depth-2 OPEF 来说却完全不同。

`0→4`：

> 一步就让 lookahead 看到了 4-bit evidence。

而

`0→1→2→4`：

> 要三个 action depth 才能看到相同精度。

于是 depth 是按“动作次数”计算，而动作的信息量完全不同。

这会天然制造：

[
\boxed{
\text{有限深度算法偏爱大跨度 refinement}
}
]

这正是你报告里观察到的“depth-2 偏向 0→4”。

所以这里不是单纯：

> depth-2 太浅。

而是：

> **lookahead depth 的定义和 heterogeneous action size 不匹配。**

这比简单继续加 depth 更值得先解决。

对 MVS-A，我建议直接把 action family 冻结成：

[
\boxed{
0\to1,\qquad
1\to2,\qquad
2\to4
}
]

先完成纯 progressive-information Gate。

到了 MVS-B 有：

[
b_h>0
]

以后，跨级动作才真正有物理意义，因为：

[
0\to4
]

可以少支付多个 header / round / retransmission cost。

# 六、P-OTS 赢得很多，目前也不能直接判 O-PEF 机制失败

`POTS` 当前排序是：

```python
np.argsort(-np.abs(L), axis=1)
```

也就是 fusion scheduler 在没有付出任何通信之前就“知道”所有 UAV 的连续：

[
|L_i|.
]

文档其实已经正确标记它为 `OTS-Oracle-Order`。

问题是最后 Gate G4 又要求 O-PEF 必须击败它。

这两个 policy 的**信息结构不一样**。

O-PEF owner 在动作前只知道：

[
\mathbf z_t
]

和静态模型。

P-OTS 却在第一个 payload bit 发出前已经知道：

[
|L_1|,\ldots,|L_N|.
]

也就是说它获得了所有传感器的**private realized evidence magnitude**用于调度。

因此 P-OTS 的 7.94 bit 很有价值，但应该解释为：

[
\boxed{
\text{private-evidence-aware ordering oracle}
}
]

而不是 G4 的公平 hard baseline。

报告本身已经注意到了这一点，但 Gate 设计还没有跟着改。

真正公平的强 baseline 我建议增加：

[
\boxed{\text{1-bit-seeded P-OTS}}
]

即所有 UAV 先支付 1 bit：

[
B=N,
]

owner 得到真实的 coarse evidence 后，再根据这些**已经付费获得的信息**安排后续 1→2→4 refinement。

这样同时具有：

- realized evidence；
- ordering；
- progressive precision；
- 相同信息约束。

这个 baseline 才真正能回答：

> O-PEF 的 posterior-aware joint selection 是否优于简单的“先粗报、后排序”。

这个对论文非常重要。

# 七、G1 现在是“实现自洽”，还不是“独立数学认证”

`ExactDP.solve()` 和 `bellman_residual()` 最后都通过同一个 `_pass()` 计算 Bellman operator。

所以：

[
\max_x|V-TV|=0
]

是很好的自洽测试，但存在一个问题：

> 如果 `_pass()` 里的 transition probability 本身共同写错，solve 和 residual 会一起错，仍然得到 0。

当前 smoke test 也是同样的路径。

建议给 G1 增加几个真正独立的数学 invariant，其中最强的是：

[
\sum_{x'}P(x'|x,a)=1,
]

posterior martingale：

[
\sum_{x'}P(x'|x,a)p(x')=p(x),
]

以及刚才的 information monotonicity：

[
\boxed{
E[R_{\rm stop}(x')|x,a]
\le
R_{\rm stop}(x).
}
]

再增加一个独立 `PolicyEvaluator`，对 Exact-DP policy 重新计算：

[
J^{\pi_{\rm DP}}(x_0).
]

必须满足：

# [ \boxed{ J^{\pi_{\rm DP}}(x_0)

V^\star(x_0)
}
]

到双精度误差。

这个 Gate 比单纯 Bellman residual 强很多。

# 八、当前 Monte Carlo 评价还有一个统计口径问题

现在 `evaluate()` 每次在**被评价的同一批 H0 样本**上寻找 randomized NP threshold，然后再在同一批样本上报告：

[
P_{FA}=0.05.
]

所以报告里：

[
P_{FA}=0.0500\pm0.0000
]

并不是“20 次实验 false alarm 都极其稳定”。

而是：

[
\boxed{
P_{FA}=0.05
\text{ 是 evaluation procedure 强制出来的。}
}
]

这在画 ROC 时可以接受，但不能作为 false-alarm constraint robustness 的证据。

而且 `pd_target` 用 20-run all-neighbor mean，adaptive sweep 却主要在一个 seed 上选择 operating point；随后又用 20-run 复核。

于是你已经出现了：

单次 sweep：

[
P_D^{OPEF3}=0.8378<0.8381
]

但 20-run：

[
P_D^{OPEF3}=0.8399>0.8381.
]

这说明现在 matched target 就位于 MC uncertainty 附近。

MVS-A 状态空间是有限的，其实完全可以更进一步：

> **对 table policy 做 exact forward probability propagation。**

在 H0 和 H1 下分别从 root state 开始沿 policy DAG 推概率质量，就可以精确算：

[
P_D,\quad P_{FA},\quad
E[B|H_0],\quad E[B|H_1].
]

这样 DP/OPEF 的 MVS-A 主结果甚至不需要 Monte Carlo。

Monte Carlo 保留给：

- continuous oracle OTS；
- 后面的 channel；
- MVS-B/full system。

这会大幅提高 MVS-A 的认证强度。

# 九、我建议接下来严格按这个顺序操作

1. **冻结当前 commit 为 `MVS-A-v0-diagnostic`，不要删除结果，也暂时不要进入 MVS-B。** 当前结果非常有价值，因为已经暴露了真正的问题；但把 G2/G3/G4 从 `FAIL` 改为 `REOPEN/PENDING-METRIC-FIX`。G0 保留 PASS，G1 改成 `PASS-self-consistency / pending independent certification`。
2. **先做 MVS-A-R1 的 objective/evaluation 修复。** 把 `μ,μ` 改成真正的 ((\mu_M,\mu_F)) 或者更直观地参数化成“risk scale + terminal decision threshold”。STOP 时直接输出 H0/H1 terminal decision，计算真实 (P_D,P_{FA})，不要再拿另一个 NP threshold 替换 DP 的终端判决。post-hoc NP ROC 可以保留，但只能命名为 `terminal-statistic ROC diagnostic`。
3. **重写 G2。** 新增固定 policy 的 exact evaluator，计算
   [
   J^\pi=E[B]+\mu_MP_M+\mu_FP_{FA}.
   ]
   Exact DP 必须满足
   [
   J_{\rm DP}\le J_{\rm OPEF1/2/3}.
   ]
   然后再在满足相同 QoS 的 policy 间比较通信成本。原来的“同 μ 只比较 bits”应删除。
4. **做一个非常关键的 2×2 solver 实验：`adjacent-only / cross-level` × `depth-2 / depth-3(4)`。** MVS-A 主版本只保留 `0→1→2→4` adjacent refinement。若 adjacent-only 后 solver gap 大幅下降，就说明问题核心不是“depth 不够”，而是“variable-size action 把 finite-horizon lookahead 搞偏了”。如果仍然明显偏离 DP，再考虑更深 lookahead。
5. **不要用普通“action depth”作为最终 scalable solver 的唯一 horizon。** 更合理的是做 **resource-bounded lookahead**：按照累计未来 bit/radio cost 截断，例如未来 2/4/6 bit，而不是未来 2/3 个动作。到了 MVS-B，直接用 cumulative radio resource
   [
   \sum c_a^{radio}
   ]
   作为 horizon。这样 `0→4` 和多个 incremental actions 不会因为“动作数不同”得到不公平的前视能力。
6. **重构 baseline Gate。** `POTS-Oracle-Order` 和 `OTSF-Oracle-Order` 保留，但从 hard G4 移到 oracle comparison；新增 `1-bit-seeded POTS`。`B9 GlobalFixed` 和 `B11 Static Progressive` 应成为最关键的公平 baseline。尤其是修正后的 Exact constrained DP 在相同信息结构下应当构成它们的上包络；如果做不到，先找实现/评价 bug，不讨论创新性。
7. **最后才重新判断 O-PEF 是否值得进入 MVS-B。** 如果修正以后 Exact-DP constrained frontier 正常、OPEF-2/3 接近 DP，而且明显优于 GlobalFixed/Static/1-bit-seeded-POTS，就进入 MVS-B。若 DP 很强而 OPEF 远离 DP，才是真正的 solver 问题；若 OPEF 已接近 DP，但连公平 static/progressive baseline 都赢不了，那才说明“realized-message adaptive acquisition”在这个 MVS-A 模型里的创新价值不足，需要重新设计机制，而不是继续堆深度。

## 最终判断

这次更新**不是失败**，反而把 MVS-A 的作用发挥出来了：它确实在进入通信 channel 和 UAV geometry 之前暴露出了理论—实现接口问题。

但我会推翻当前报告中的一个关键行动建议：

> ~~“G2=50.2%，所以继续加深 lookahead。”~~

现在更合理的是：

[
\boxed{
\textbf{先修 objective/evaluation consistency}
\rightarrow
\textbf{去除 MVS-A cross-level horizon bias}
\rightarrow
\textbf{重定义 solver gap}
\rightarrow
\textbf{再决定是否需要加深 solver}.
}
]

尤其是 **cross-level dominance + Bayes/NP mismatch** 这两个点，我认为是下一轮最值得先验证的。它们修正以后，当前所谓的 `50.2% solver gap`、`μ→∞ ceiling` 和 `P-OTS 明显占优` 三个现象都有可能发生明显变化。

如果按科研优先级，我建议下一次提交就命名成类似 **`MVS-A-R1: objective-consistent constrained-policy audit`**，先只做这一轮，不碰 MVS-B、OTFS、channel 和 MARL。
