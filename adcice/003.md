# 2. 4.9007 很强，但目前还不能叫“精确 CMDP oracle”

当前 `run_mvsa_r11.py` 先固定：

[
s\in{16,64,256,512,1024,4096}
]

和预设的 (\eta) 网格，再加少量 refined points，总共得到 56 个 Exact-DP deterministic policies，然后只在这 **56 个 policy columns** 上运行 `linprog`。

所以现在严格应该叫：

[
\boxed{
B_{\rm RMP}=4.9007
}
]

其中 RMP = restricted master problem。

它是一个**已经找到的可行 CMDP 解**，因此对于真正全局 optimum：

[
B_{\rm CMDP}^\star\le4.9007.
]

但还没有证明不存在第 57 个、当前 ((s,\eta)) 网格没生成的 deterministic policy，使 LP 继续下降。

好消息是：你现在已经拥有 ExactDP，所以这个问题可以非常漂亮地彻底解决，而且几乎不需要新理论。

### 用 column generation 给 4.9007 做真正的全局最优证书

Restricted master：

[
\min_w\sum_k w_k B_k
]

s.t.

[
\sum_kw_kP_{FA,k}\le\alpha ,
]

[
\sum_kw_kP_{M,k}\le\beta ,
]

[
\sum_kw_k=1.
]

从 LP 中取得 dual：

[
\lambda_F\ge0,\qquad
\lambda_M\ge0,\qquad
\nu.
]

然后直接调用你现有的 ExactDP 解 pricing problem：

[
\boxed{
\min_\pi
\left[
B_\pi+
\lambda_M P_{M,\pi}
+
\lambda_F P_{FA,\pi}
\right].
}
]

也就是 ExactDP 已经在做的 Lagrangian。

定义 reduced cost：

# [ r(\pi)

B_\pi+
\lambda_MP_{M,\pi}
+
\lambda_FP_{FA,\pi}
-\nu.
]

若：

[
r(\pi^\star)<-\epsilon,
]

把新 policy 加入 LP，重新求。

如果最终：

[
\boxed{
r(\pi^\star)\ge-\epsilon
}
]

那么才能正式写：

[
\boxed{
B_{\rm DP}^{CMDP}=4.9007
}
]

为**全局认证的 finite-CMDP optimum**。

这会是非常强的理论闭环：LP master + Exact-DP pricing oracle。

# 3. 当前 R2 最大的问题：代码实现的是“硬总预算”，不是 receding horizon

这是本轮最重要的新发现。

`rbl.py` 写的是：

# [ V_h(x)

\min
\left{
R_{\rm stop},
\min_{a:c_a\le h}
[c_a+EV_{h-c_a}(x')]
\right}.
]

这个递推本身没问题。

关键在**实际执行**。

你当前 `exact_evaluate_rbl()` 初始化：

[
(x_0,H)
]

执行一次 cost (c_a) 的动作后，真正进入：

[
(x',H-c_a),
]

然后继续从 (H-c_a) 做决策。

因此当前 policy 实际满足：

[
\boxed{
\sum_t c_{a_t}\le H
}
]

这是一个 **hard episode communication budget**。

也就是说现在实现的是：

[
\boxed{
\text{Budget-Constrained DP}
}
]

而不是上一轮定义的：

[
\boxed{
\text{Resource-Bounded Receding-Horizon Solver}.
}
]

两者不是一回事。

# 4. 真正的 receding-horizon 实现其实非常简单

你现在已经算出了：

```python
policies[h, idx]
```

所以不用重写 RBL recursion。

对于固定 lookahead (H)，真正部署的 policy 应定义为：

# [ \boxed{ \pi_H^{RH}(x)

\text{policies}[H,x].
}
]

执行一个 action 后到达 (x')，**重新恢复完整 lookahead (H)**：

[
x_t
\xrightarrow{\pi_H}
x_{t+1}
\xrightarrow{\pi_H}
x_{t+2}.
]

而不是：

[
H\to H-c_a\to H-c_a-c_b.
]

代码上甚至可以先直接：

```python
policy_rh = policies[H].copy()
sd = exact_stop_distribution(ss, policy_rh)
```

因为 `exact_stop_distribution()` 是 state-only evaluator，每到一个新 state 都重新读取：

```python
policy_rh[idx]
```

这正好就是 receding horizon。

所以建议把当前 RBL 拆成两个名字：

- **RB-HardBudget**：保留当前 `(state,h)` evaluator；
- **RBL-RH**：真正 receding-resource lookahead，作为 proposed scalable solver。

当前 hard-budget 结果不用删除，它本身也是一个有意义的 ablation。

# 10. Online RBL 应该怎么写

不要再生成：

[
23^4
]

张完整表。

直接从当前真实状态 (x) 出发：

[
F(x,h).
]

只展开 horizon 内能到达的 child states。

伪逻辑：

```text
Solve(x, h):
    best = R_stop(x)

    for feasible action a:
        if cost(a) > h:
            continue

        Q = cost(a)
        for child x':
            Q += P(x'|x,a) * Solve(x', h-cost(a))

        best = min(best, Q)

    return best
```

使用局部：

[
(x,h)\rightarrow V
]

memoization。

部署时：

```text
每收到一个新 message：
    再次调用 Solve(current_state, H)
```

即 receding。

MVS-A 可以做一个非常强的 equivalence audit：

# [ \boxed{ a_{\rm online}(x,H)

a_{\rm table}(x,H)
}
]

对所有可达 state，或者至少全 279841 state 全测。

一旦这个 Gate 过了，就删掉 MVS-B 对全状态表的依赖。

# 11. 然后才正式进入 MVS-B，而且建议分三小步

现在我仍然赞成 SystemModel 的 N=8 MVS-B 方向，但不要一次把 Rician + header + packet loss + explicit retransmission 全加进去。

### MVS-B0：Protocol-cost activation

保持：

[
p_{\rm succ}=1
]

先加入：

[
b_h=16
]

和 cross-level actions：

[
0\to1,;0\to2,;0\to4,;0\to8,\ldots
]

这一步专门验证 R1 中：

> cross-level 在 (b_h=0) 被弱支配

到了：

[
b_h>0
]

后确实恢复价值。

这会形成一个非常漂亮的理论闭环。

### MVS-B1：Heterogeneous ARQ-collapsed cost

再加入：

# [ \bar c_a

\frac{b_h+r'-r}{p_i^{succ}}.
]

SystemModel 已经定义这个模型。

此时注意：

[
\bar c_a
]

通常不再是整数。

所以现在 `V[h-c_a]` 这种 ndarray 整数索引写法不能直接搬过去。

这也正是为什么现在先把 solver 改成 sparse recursive planner 很重要。

### MVS-B2：Explicit packet-loss audit

最后再做：

# [ x'

\begin{cases}
x_a^+,&p_{\rm succ}\
x,&1-p_{\rm succ}
\end{cases}
]

与 collapsed 版本 A/B。

只有这一层涉及 failure self-loop，不再是简单 refinement DAG。

这样每一步只引入一个新变量。

# 12. MVS-B 最重要的实验仍然应该是 anti-correlation

SystemModel 已经把三个 regime 定义得很好：

[
\text{Positive},
\quad
\text{Independent},
\quad
\text{Anti-Correlation}.

尤其：

[
\boxed{
\text{强 sensing UAV}
\neq

的 anti-correlation 是 O-PEF 最应该赢的环境。

这是之后真正体现：

[

价值的地方。

所以不要再继续在 MVS-A 调 0.1% 性能。
