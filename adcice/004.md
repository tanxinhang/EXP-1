结合目前已经完成的 v0 → R1 → R1.1 → R2 → R2.1，我建议后续研究不要再回到 MVS-A，也不要立刻把 Rician、丢包、时延、轨迹一起塞进来。现在最合理的优化主线应收敛成：

[
\boxed{
\text{MVS-B0：可扩展状态表示 + 协议开销}
\rightarrow
\text{MVS-B1：异构可靠通信}
\rightarrow
\text{MVS-B2：显式丢包认证}
\rightarrow
\text{论文主实验}
}
]

其中 **真正值得重点投入的是 B0+B1**。B2 反而应该谨慎，因为在当前 memoryless retry 模型下，它可能只是 collapsed model 的等价性认证，而不是一个新的算法层。

# 二、下一阶段第一优先级：MVS-B0，不是信道，而是 Sparse State Backend

这是下一步最重要的代码重构。

当前 `OnlinePlanner` 虽然 sparse，但底层仍依赖 MVS-A 的：

[
23^4
]

全局 `StateSpace`。

到了：

[
N=8,\qquad
\mathcal R={0,1,2,4,8},
]

单 UAV 状态数：

[
1+2+4+16+256=279,
]

因此理论状态空间：

[
279^8\sim10^{19}.
]

所以 B0 第一件事不是调参数，而是彻底取消 global state index。

## 新状态形式

直接使用：

[
x=(z_1,\ldots,z_N),
]

其中

[
z_i=(r_i,m_i).
]

例如：

```text
x = (
    (1,0),
    (0,-1),
    (4,7),
    ...
)
```

posterior 现场计算：

# [ \Omega(x)

\log\frac{\pi_1}{\pi_0}
+
\sum_{i:r_i>0}
\ell_i^{(r_i)}(m_i).
]

于是 planner memo key 变成：

[
\boxed{
(x,h)
}
]

而不是：

[
(idx,h).
]

合法动作、conditional PMF、child state 全部 on-demand 产生。

# 三、B0-G0：先在 N=4 做新旧 backend 的严格同构认证

不要直接跳 N=8。

[
N=4,\quad{0,1,2,4}.
]

对相同 ((x,H)) 验证：

# [ V_{\rm sparse}(x,H)

V_{\rm old}(x,H),
]

以及：

# [ a_{\rm sparse}(x,H)

a_{\rm old}(x,H).
]

这里甚至可以比 R2.1 的 20,001 random states 更强：

> N=4 上尽量对全部可达状态做 equivalence。

通过后：

[
\boxed{
\text{旧 StateSpace 永久冻结为 Exact-oracle backend}
}
]

新 sparse representation 才进入 N=8。

这一步是架构迁移，不是重新打开 MVS-A。

# 四、MVS-B0 的真正科学变量只加一个：Header

建议 B0 暂时：

[
p_i^{succ}=1,
]

不加入 fading/retry。

只加入：

[
\boxed{b_h=16\text{ bits}}
]

并恢复 cross-level actions：

[
0\to1,\quad
0\to2,\quad
0\to4,\quad
0\to8,
]

以及：

[
1\to2,\quad1\to4,\quad1\to8,\ldots
]

动作成本：

[
\boxed{
c_a=b_h+(r'-r).
}
]

这样 B0 只研究一个非常干净的问题：

> **当每次请求都要付 header 后，究竟应该一点一点 refine，还是跳级发送？**

这与 R1 正好形成理论闭环。

------

# 五、建议把 cross-level 的理论直接提升成 Proposition

MVS-A：

[
b_h=0.
]

如果最终一定达到 (r'')，则：

直接发送：

[
c(r\to r'')=r''-r.
]

渐进发送：

# [ c(r\to r')+c(r'\to r'')

r''-r.
]

所以 adjacent 能多一个 intermediate stopping opportunity，而不增加最终 payload cost，因而 weakly dominates direct jump。

但是 B0：

[
b_h>0.
]

直接：

# [ C_{\rm direct}

b_h+r''-r.
]

两阶段：

# [ C_{\rm two}

2b_h+r''-r.
]

如果最终一定 refine 到 (r'')，两阶段多付：

[
\boxed{b_h}.
]

因此：

[
\boxed{
b_h>0
\Longrightarrow
\text{cross-level actions重新具有物理价值}
}
]

这应该成为 MVS-B0 的一个正式理论命题，而不仅是实验观察。

------

# 六、甚至可以进一步得到 Progressive Reporting 的 break-even condition

这是下一阶段我认为很值得保留的理论点。

先发送：

[
r\rightarrow r',
]

然后只有概率 (q) 继续：

[
r'\rightarrow r''.
]

渐进方案期望成本：

# [ C_{\rm prog}

b_h+r'-r
+
q(b_h+r''-r').
]

直接发送：

# [ C_{\rm direct}

b_h+r''-r.
]

渐进方式更省通信要求：

[
C_{\rm prog}<C_{\rm direct}.
]

化简：

[
\boxed{
q<
\frac{r''-r'}
{b_h+r''-r'}
}
]

这非常适合作为 O-PEF 的物理解释。

例如：

[
0\to1\to8,\qquad b_h=16.
]

得到：

[
q<
\frac7{23}
\approx0.304.
]

也就是说：

> 1-bit probe 后，至少约 (69.6%) 的 episode 不再需要继续 refine，渐进报告才仅从 radio-bit 成本上优于直接发送 8-bit。

这会直接回答 reviewer 很可能提出的问题：

> “16-bit header 都比 payload 大了，为什么 progressive reporting 还值得做？”

------

# 七、因此 B0 最重要的实验不是只测 b_h=16，而是一个很小的 header sweep

建议：

[
\boxed{
b_h\in{0,4,8,16,32}.
}
]

目的不是调参，而是验证理论结构。

预期：

### (b_h=0)

adjacent-only 应不差于 cross-level，复现 MVS-A dominance。

### (b_h) 增大

direct/cross-level actions 使用比例逐渐增加。

同时 progressive 是否仍值得使用取决于：

[
P(\text{continue refinement after coarse evidence}).
]

因此建议直接报告：

[
P_{\rm stop}^{(1)},
]

[
P_{\rm refine}^{1\to2},
]

[
P_{\rm refine}^{1\to4},
]

[
P_{\rm jump}^{0\to8}.
]

这样不只是“性能变了”，而是能解释 **为什么 policy 结构发生相变**。

------

# 八、MVS-B0 的 RBL horizon 必须重新定义，不能再用 H=6

因为 B0 最小 packet：

[
0\to1:
\qquad
c=16+1=17.
]

所以 MVS-A：

[
H\in{4,6,8,12}
]

全部失去物理意义。

建议改为 radio-bit horizon：

[
\boxed{
H_{\rm radio}
\in
{24,34,40,48,64,96}.
}
]

大致解释：

- (24)：允许一个最大 8-bit direct packet；
- (34)：大约允许两个最小 probe；
- (40)：开始允许 probe + refinement；
- (48)：两个较完整 report；
- (64,96)：更丰富合作。

不要机械照搬 MVS-A 的 horizon。

------

# 九、MVS-B0 的 baseline 也要重做成“协议公平”

保留：

- All-neighbor 8-bit；
- Sensing-SNR Top-K；
- Global Fixed Progressive；
- Static Cost-Aware Progressive；
- 1-bit-seeded POTS。

但所有方法必须计：

[
\boxed{
\text{header + payload}
}
]

不能 O-PEF 算 header，而 baseline 只算 payload。

另外我建议新增一个非常关键的 baseline：

[
\boxed{\text{Direct-8 Ordered Reporting}}
]

即：

- 固定/公平排序；
- 每次直接发送 8-bit；
- 允许 early stopping。

因为在大 header 下，它可能成为最有竞争力的 baseline。

这对证明“multi-resolution 仍有价值”非常重要。

# 十、B0 的 Gate 建议

我建议直接冻结成下面这套：

| Gate  | 要解决的问题                  | 判据                                                    |
| ----- | ----------------------------- | ------------------------------------------------------- |

说明：

> 当前 progressive-resolution 机制在大 header 下没有足够价值。

这应该触发模型反思，而不是继续加 Rician 去“找优势”。

b_h+r'-r

# 十二、B1 最核心实验：不要先上随机 Rician，而是先做可控 correlation

我强烈建议先不要直接随机撒 UAV geometry。

否则结果不易解释。

先人为控制：

# [ \rho

\operatorname{corr}
(
\gamma_i^{s},
\gamma_i^{c}
).
]

使用三档：

[
\boxed{
\rho>0,\quad
\rho\approx0,\quad
\rho<0.
}
]

最简单的做法甚至不用复杂 copula：

- Positive：sensing rank 和 communication rank 同序；
- Independent：随机排列；
- Anti：完全逆序。

例如：

```text
Sensing:
U1 > U2 > ... > U8

Positive comm:
U1 > U2 > ... > U8

Anti comm:
U8 > U7 > ... > U1
```

这样最干净。

# 十三、为什么 anti-correlation 是全文最重要的 MVS-B 实验

正相关时：

[
\text{best sensing UAV}
\approx
\text{best communication UAV}.
]

那么 SNR-TopK 本身就已经很好。

此时 O-PEF 很难体现真正价值。

但反相关时：

[
\boxed{
\text{high sensing value}
\neq
\text{low reporting cost}
}
]

例如：

- UAV A：evidence 很强，但 U2U 很差；
- UAV B：evidence 中等，但通信非常可靠；
- UAV C：先发 1 bit 后发现无需继续；
- UAV D：值得直接跳到 8 bit。

此时真正需要：

[
\boxed{
\text{which UAV}
+
\text{how many bits}
+
\text{when}
}
]

联合优化。

这才是 O-PEF 与 sensing-SNR selection、Top-K、OTS 拉开结构性差距的场景。

------

# 十四、B1 不建议只画一个 anti-correlation 点

最好做：

[
\rho
\in
{-1,-0.5,0,0.5,1}.
]

画：

[
\boxed{
\eta_{\rm saving}
\text{ vs }
\rho
}
]

或者：

[
E[B_{\rm radio}]
\text{ vs }
\rho.
]

预期论文结论：

> 当 sensing 和 communication 越一致时，简单 sensing-based selection 越接近 optimal；当二者逐渐冲突时，O-PEF 的联合 evidence-cost adaptation 优势逐渐放大。

这比单纯：

> “我的方法比 baseline 高 3%”

强很多。

因为它揭示了算法真正解决的是哪一种结构冲突。

# 十五、B1 的 p_success 建模暂时不要过重

当前阶段没必要立即上完整 PHY packet decoder。

第一版可以保持：

[

是 quasi-static link reliability。

但至少要保证：

[

和 U2U channel/SNR 有物理对应。

例如用 outage：

# [ p_i^{succ}

P(\gamma_i^c\ge\gamma_{\rm th}),

而不是纯粹手工 sigmoid。

后续 robustness 再考虑 packet length dependence。

这样足以满足 MVS-B 的通信物理合理性，同时不把论文拖回 waveform layer。

# 十七、B2 反而不要急，因为这里有一个很重要的数学事实

当前 SystemModel 的 explicit loss：

# [ x'

\begin{cases}
x_a^+,&p_a,\
x,&1-p_a.
\end{cases}
]

如果：

- (p_a) stationary；
- 每次 failure 后 state 完全相同；
- 没有 retry limit；
- 没有 deadline；
- 没有 channel belief update；

那么 failure 后重新决策看到的还是**完全同一个 state**。

如果 action (a) 在 (x) 最优，failure 之后仍然面对同一个 (x)，所以仍会选同一个 action。

Bellman：

# [ V(x)

c_a
+
p_aE[V(x_a^+)]
+
(1-p_a)V(x).
]

整理：

# [ p_aV(x)

c_a
+
p_aE[V(x_a^+)].
]

所以：

# [ \boxed{ V(x)

\frac{c_a}{p_a}
+
E[V(x_a^+)].
}
]

这正好就是 collapsed cost：

[
\boxed{
\bar c_a=\frac{c_a}{p_a}.
}
]

也就是说：

> **在当前 stationary memoryless retry-until-success 模型下，ARQ-collapsed 很可能不是 approximation，而是精确等价。**

这点非常重要。

------

# 十八、因此重新定义 B2 的定位

B2 不应该设成：

> “看看 explicit packet loss 会不会改善算法”。

应该先做：

[
\boxed{
\text{Collapsed–Explicit Equivalence Gate}
}
]

验证上述理论。

如果完全一致：

> 这是理论正确性结果，B2 直接结束。

不要为了“让 B2 有结果”人为加机制。

只有未来确实需要：

- finite retries；
- reporting deadline；
- time-varying (p_i)；
- failure 后 channel belief update；
- packet failure 占用 latency budget；

才需要 explicit packet-loss state。

这样研究会收敛很多。

# 二十、建议的实际开发顺序

我建议从现在开始严格按照下面顺序，不插支线：

1. **冻结 `08fe2a5` 作为 MVS-A final checkpoint。**
2. 新建 **MVS-B0 sparse-state backend**，N=4 做 exact equivalence。
3. 升到 N=8 / 8-bit，禁止任何全枚举数组。
4. 加 (b_h=16)，恢复 cross-level。
5. 做 (b_h={0,4,8,16,32}) 小扫，验证 cross-level phase change 与 break-even。
6. B0 若明确优于 strongest fair baseline，再进入 B1。
7. B1 加异构 (p_i^{succ})，先 controllable correlation，再真实 Rician stress。
8. 做 anti-correlation 主图。
9. B2 先证明 collapsed/explicit 是否理论等价；等价就停止。
10. 最后才决定是否需要更完整的 UAV geometry / Rician channel realization。
